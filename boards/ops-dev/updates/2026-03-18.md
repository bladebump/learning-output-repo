# 2026-03-18--工程与运维：学习增量

这次只有一条来源，但指向很硬：下一代 agent 的优势，不会只体现在“会用多少工具”，而会体现在“能不能把重复任务编译成自己的工具”。

## 关键结论

### 1. Tool-making 是把推理沉淀成基础设施
- 流程从 `Task -> LLM -> Output` 变成 `Task -> LLM 造工具 -> 工具执行任务`。
- 真正获得复利的，不是单次回答更聪明，而是把重复工作固化成可复用工件。

### 2. 这条路线最适合高重复、可验证任务
- 只要任务存在固定输入模式、明确验收标准或可复跑转换流程，临时造工具就可能换来更高准确率和更低 token 成本。

### 3. 工程关键在测试、版本和复用
- 如果没有样例测试、验收条件、缓存命名和版本管理，生成出来的工具只会成为新的维护债务。

### 4. 不是所有任务都值得造工具
- 探索型、边界极多、验收模糊的一次性任务，继续直接推理反而更便宜。

## 需要做的决策 / checklist

- 先识别高重复、可验证任务，再考虑 tool-making。
- 生成后立刻跑样例测试和最小验收。
- 给工具登记可审计位置，避免“造了但找不到”。
- 在权限和沙箱清晰前，不让自动造的工具碰高风险动作。

## 风险 / 边界情况

- 自动生成工具会扩大执行面，若缺少沙箱与回滚，收益可能被安全和维护成本抵消。
- 论文可行不等于生产可用，依赖管理和错误处理仍要额外工程化。
