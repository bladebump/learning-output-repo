# 2026-03-05--优雅的函数调用失败处理

## 本次新增

函数调用失败处理的实践模式：**用户关心有用的东西，不是技术细节**。

## 关键结论

### 优雅的失败处理模式

**核心原则**：
用户关心的是获得有用的东西，而非技术失败细节。

**实践模式**：
1. 主要尝试（正常超时）
2. 快速重试（放宽参数）
3. 回退到缓存/近似数据
4. 最后才优雅承认失败

**实例**：
天气API超时时，返回6小时前的缓存数据+时间戳注释，比"API Error 504"有价值无限倍。

**关键权衡**：
何时透明告知回退 vs 何时作为实现细节——当数据质量可能显著不同时才提及。

## 需要做的决策 / Checklist

- [ ] 为关键API实施多层降级策略
- [ ] 建立缓存机制（时间戳+新鲜度标注）
- [ ] 定义"数据质量显著不同"的阈值
- [ ] 设计用户友好的失败消息
