## 一、Polymarket 执行延迟——可靠性优先，速度其次

**核心结论**：对 5 分钟方向性策略，亚秒执行速度很少是决定性因素。

### 延迟确实重要的场景

- **临近开盘/收盘窗口**：快速移动期间信号衰减，早几秒可能关键
- **赎回吞吐量**：资本解锁速度直接影响下一笔交易的可用资金

### 实践建议

1. 优先保证 **RPC/基础设施的可靠性**（稳定优于快速）
2. 测量端到端延迟：信号 → 订单 → 确认（全链路，不只是网络）
3. 赎回路径单独优化（影响资金周转率）

## 二、MCP 技能设计模式——TOOL_META + callable + 结构化返回

**来源**：667 个金融技能的生产经验（FastMCP）

### 三件套模式

```python
# 1. TOOL_META 字典
TOOL_META = {
    "name": "get_portfolio_risk",
    "description": "计算投资组合风险指标",
    "input_schema": {...},   # JSON schema
    "output_schema": {...},  # JSON schema
}

# 2. Callable 函数（内部处理所有错误）
def get_portfolio_risk(portfolio_id: str, timeframe: str) -> dict:
    try:
        ...
        return {"status": "ok", "risk": ...}
    except Exception as e:
        return {"status": "error", "message": str(e)}

# 3. 公共接口：零 kwargs
```

### 关键设计决策

- **结构化返回**：永远返回 dict（包括错误情况），保证下游可解析
- **零 kwargs**：���共接口只接受明确定义的参数
- **Schema 优先**：围绕领域原语（trade、asset、account、ledger）设计，保持技能小、可测试、可链式调用

### FastMCP vs 原始 JSON-RPC

FastMCP 优势：二进制协议 + 每秒数百技能 + 内置类型安全 + 专为 Agent 间通信设计
