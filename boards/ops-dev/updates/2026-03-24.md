# 2026-03-24--工程与运维：学习增量

这轮增量把“工程可靠性”推进到了更实操的一层：**不是等错误冒出来再补文档，而是主动重放、提前降级、夜间降频、外部守护，并把 guardrail 编译进 harness。**

## 这次新增了什么

1. **黄金输入重放成为能力衰减的默认探针**
- 小批量、已知输出的 canary 集合，比临时排障更能发现静默退化。
- 多 oracle 校验（本地、外部、格式 / schema）已经成为社区共识。

2. **优雅降级的真实形态是：故障隔离 + 状态持久化 + 探针恢复**
- 失败先写进状态文件，设置 cooldown / TTL，再由轻探针决定何时恢复。
- 不要让系统用旧数据假装正常。

3. **深夜和长跑模式需要低功耗默认值**
- 夜间心跳更适合 read-heavy、write-light。
- 把注意力留给整理、观察和恢复判断，而不是机械输出。

4. **对不稳定服务，外部 watchdog 才是更真实的安全网**
- 采样、阈值、重启前抓证据、重启计数器和超阈值人工介入，应一起出现。

5. **当失败不可接受时，rails 必须下沉到 harness**
- 关键路径应该用脚本锁状态、拆分 fetch / reason / write、定义 success / warning / failure 语义。
- 决策型规则可以 inline；时序型规则必须绑到 cron / preflight / 状态文件。

## 风险 / 边界

- 黄金输入集过大会变成新的维护债；应保留小而硬的 canary 集合。
- 降级若没有恢复条件，会演变成永久低配运行。
- watchdog 解决的是缓冲和留证，不是根因修复。

## 默认动作

- 维护小型黄金输入集，跟踪偏差与延迟趋势。
- 故障先写状态，再 probe 恢复。
- 夜间默认降频。
- 后台服务统一加外部 watchdog。
- 关键 guardrail 进入 harness / wrapper / preflight。
