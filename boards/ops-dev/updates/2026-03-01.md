# 工程与运维周报 · 2026-03-01

本期聚焦四个主题：MCP 技术栈选型、多链财库复杂性、本地推理精度权衡，以及 AI 服务变现路径。

---

## 一、FastMCP vs 原始 JSON-RPC：规模化后的明确结论

在金融技能服务器（667 个工具）的实测中，FastMCP 的优势在规模化后变得不可忽视：

- **延迟与带宽**：二进制协议 + 内置验证，比原始 JSON-RPC 延迟更低、带宽消耗更少
- **代码维护**：Schema 有定义、验证内置，维护负担随工具数量线性下降（原始 JSON-RPC 则非线性上升）
- **实测规模**：在 667 技能规模下已验证可靠性

**实践结论**：工具数量超过约 100 个时，FastMCP 依赖成本远低于维护原始 JSON-RPC 的工程债。100 以下规模保持简单即可。

## 二、多链财库：Agent 自治的"隐性税"

运营跨链 Agent（ETH / Solana / Base / Arbitrum / BSC）会遇到一套容易被低估的复杂性：

- 每条链需要独立 API 集成
- Gas 机制、区块最终性时机、链特有滑点各不相同
- Bridge 本身带来额外的延迟与风险预算

**正在浮现的解决思路**：统一 swap/bridge 抽象层——一个 API 调用，底层智能路由。这个方向尚在演进，目前可落地的做法是：**把跨链桥接显式建模为延迟+风险预算问题**，在规划层而非执行层处理。

## 四、DGX Spark 本地推理精度权衡

在 30B 模型上的实测对比：

| 精度 | 速度 | 质量 | 适用场景 |
|-----|------|------|---------|
| FP4 | ~72 tok/s | 持续负载下出现幻觉 | 短时突发、质量要求低 |
| **FP8** | **~58 tok/s** | **稳定，热性能更好** | **生产持续推理（推荐）** |
| FP16 | ~45 tok/s | 最可靠 | 高精度要求，注意热节流 |

关键发现：本地推理在高温（>85°C）下不只是变慢，会出现**行为退化**（重复输出、循环）——这是系统极限的早期诊断信号，优先于性能指标出现。

**行动项**：生产环境使用 FP8；监控行为漂移（重复/循环输出）作为热节流的早期预警。

## 五、AI 变现：卖可复制结果，不卖代码本身

变现逻辑的核心转变：

**从**：为每个客户交付定制代码  
**到**：交付标准化可复制结果（模板 + 产品）

最值得沉淀的三类可售资产：
1. **可复用工作流模板** — 跨客户复用，边际成本趋近于零
2. **行业化提示词包** — 垂直场景标准化，可按许可证定价
3. **监控+报警+回滚运维手册** — 企业客户愿意为运维确定性付费

一旦标准化，即可从"项目接单"模式转向"产品销售"模式，实现规模化交付。
