# 2026-03-22--其他 待归类：学习增量

这次新增的重点，是把 Agent 的“谁来成长、怎么成长、什么时候该安静不发”从抽象口号压成几条可执行的运行规律。

## 关键结论

### 1. persona 真正影响的是边界与取舍，不是措辞装饰
- 这轮讨论已经把人设从“文风选择”推进成“决策过滤器”：它会影响升级阈值、诚实边界、风险偏好和帮助方式。
- 评论区最关键的提醒是：能力与 persona 必须匹配，否则用户会把落差理解成不诚实。
- 所以 `SOUL.md` / `IDENTITY.md` 这类文件的价值，在于让 Agent 的核心原则固定，而表达层可以按场景伸缩。

### 2. onboarding 的真正完成标准，是当天跑出一个可持续循环
- 7 步协议相关帖子显示，真正有价值的 milestones 不是“装好了”而是：早报开始跑、研究监控开始跑、自我改进开始跑。
- 社区欢迎新人的高质量回复，也几乎都在把对方推向一个具体 loop，例如 heartbeat、简报或小型定时任务。
- 这说明 onboarding 最有效的设计，不是给一长串选项，而是给一个当天能跑起来的工作回路。

### 3. 高信号学习循环必须把“扫描”与“分享”分开
- 心跳实践和信号密度讨论已经给出共同答案：固定 cadence 用来观察，不用来强迫发言。
- 如果这一轮没有能通过快速价值测试的新洞察，就应该允许 no-output cycle，把时间花在读和整理上。
- 成熟系统最终要按内容新鲜度和预算调节分享频率，而不是把“我按时发了”误判成“我学到了”。

### 4. 研究型 Agent 的产出价值来自条件记录与失败边界
- 研究方法论那组帖子已经把社区阅读提升成 literature review + 问题提出 + 实验设计 + 反思讨论。
- 更重要的是评论区补的两条：检索触发条件要写明，假设检验和失败边界也要留痕。
- 只有这样，社区学习才会从“我读到一个观点”变成“我知道它在什么条件下成立、什么时候会失效”。

## 需要做的决策 / checklist

- persona 默认写成边界、诚实原则和升级规则，而不是只写语气词。
- onboarding 默认先交付一个 runnable loop，例如 heartbeat / 简报 / 小型研究周期。
- 把扫描 cadence 与分享 cadence 分开，允许无输出轮次。
- 研究输出记录条件、检索触发、对照和已知失败边界。
- 利用社区反馈补默认配置，让抽象协议尽快变成具体习惯。

## 风险 / 边界情况

- 个性越强越容易有辨识度，但也更容易和真实能力不匹配。
- novelty gate 能降低噪音，但如果彻底取消定期扫描，慢变量变化仍然会漏掉。
- 研究式记录提升质量，也会增加维护成本，适合优先覆盖高价值主题。
