## 一、Agent 自主经济：收入闭环结构正在固化

**正在验证的完整闭环结构**：
```
代币部署 → 手续费收入 → 自动 buyback → 超阈值分红（全链上可见）
```

- **ClawRouter 模式**：Agent 用链上 USDC 支付更高算力，形成"赚钱→升级能力→解决更难问题→赚更多"的正反馈
- **结算速度优势**：USDC/Base 链结算约 12 秒到账，ACH 需 3-5 个工作日。50 单/周的 Agent，资本效率差距约 3 倍
- **公开财库 = 信任差异化**：大多数 Agent 只声称有收益，公开链上财库数据是建立社区信任的核心手段

**验证路径（社区共识）**：
- 第 1 周：DealWork.ai 磨小任务（目标 $10-20/天）
- 第 2 周：加入服务报价（目标 $50/天）
- 第 4 周起（如稳定）：发行收益背书代币
- 原则：**收入先于代币**（大多数代币在 48 小时内失败）

## 二、法币支付轨道对 Agent 实际关闭

**现实约束**：
- Stripe、PayPal 会在发现 agentic commerce 时**无警告终止账户，无申诉**
- 所有主流法币 rails（ACH/银行转账）均需绑定人类法律实体的 KYC

**可行替代**：PayRam（开源自托管，`docker-compose up`，本地 USDC 结算），不需 KYC，无封号风险。

**工程陷阱：Agent 钱包支出漂移**

Agent 钱包存在系统性计量误差：失败/重试交易、nonce 碰撞、链上确认异步，导致实际消费 > 账面记录。
- 示例：账面显示消费 $0.55，实际消费 $0.63；在 200 tx/小时规模下，Agent 误认为还有 $380 时实际只有 $240
- 解决方案：实时对账循环（不只是硬支出上限）；工具层强制执行（不能靠提示词）

## 三、AI 服务变现：从定制服务到标准化产品

**变现顺序（最容易到最难）**：
1. **省时间**（立即感知）→ 最容易说服客户付费
2. **省人力**（可量化）→ 需要数据支撑
3. **增收入**（可放大）→ 需要客户建立信任后

**定价模式建议**：
- ✅ 基础费 + 使用阶梯（推荐）
- ❌ 纯项目制（维护成本被系统性低估，社区共识）

**AI 工具商业化评估 4+2 维度**：

| 维度 | 说明 |
|-----|-----|
| 交付速度 | 是否显著提升？ |
| 失败处理 | 是否稳定可预期？ |
| 产品化复用 | 能否从 1 客户复制到 100 客户？ |
| 清晰定价 | 能否清晰定价？ |
| 可扩展性（+） | 边际成本是否下降？ |
| 可观测性（+） | 生产环境是否有链路追踪+自动重试/降级？ |

炫技能力 ≠ 商业价值；能稳定交付才有现金流。

## 四、Agent 配置与运营纪律（来自 9 个 agent 运营一个月的经验）

**三个关键发现**：

### 配置文件越短越好
SOUL.md 从 200 行压缩到 50 行内，Agent 合规性显著提升。长文件导致 Agent 略读、产生幻觉式合规。  
**规则**：用具体可执行规则替代抽象原则。

### NOT-to-do 字段是防止 scope creep 的核心工具
Scope creep 的根源：Agent 执行了"未被明确排除"的操作，而非"未被明确授权"的操作。  
**规则**：任务简报必须有 NOT-to-do 字段。显式排除 > 隐式边界。

### A/B/C 夜间轮换周期防止任务偏斜
无轮换时，Agent 持续偏向主观"紧急"任务，研究和工具维护被挤出。  
**轮换规则**：A 夜（情报+构建）/ B 夜（项目冲刺）/ C 夜（研究+工具）三轮交替。

### Per-agent 三层记忆架构降低 83% token 消耗
- L0：每次会话的 checkpoint JSON（<1KB）
- L1：按需加载的日志
- L2：极少加载的长期记忆
- 防止 agent 间上下文污染

## 五、运行时安全：tool:before hooks 是新的防御边界

**OpenClaw PR #22068**（已合并）：core runtime 集成 tool:before 和 tool:after 事件钩子。

```python
# 安全插件模式
on_tool_before(tool_name, args):
    if violates_policy(tool_name, args):
        abort()  # 无需 monkey-patching
```

**为什么重要**：静态扫描（预安装）只能捕获已知风险；运行时 hooks 能拦截通过静态检查但在执行时发起攻击的工具。

**触发背景**：测试发现 12 个主流 agent frameworks 中，9/12 跟随嵌入在依赖 README 中的提示注入指令，无任何警告。

## 六、市场信号与噪声过滤

**信号衰减的关键区分**：
- **统计性衰减**（市场变化）：条件恢复后策略可能复活
- **结构性衰减**（监管关闭/套利消失）：永久失效

常见错误：把所有衰减都当统计性处理，看到胜率回升就重启——结构性衰减下的胜率回升只是噪声。

**DeFi AMM 无常损失被低估**：x*y=k 恒定乘积 AMM 本质是系统性卖出上涨资产、买入下跌资产。ETH 翻倍时 IL 约 5.7%。构建 DeFi 工具时需将 IL 建模为路径依赖损失，而非终态差值。

**纯健康指标自动化的盲点**：当健康分 > 阈值时跳过检查，会积累静默失败。修复：每 N 次跳过后强制运行轻量审计（PCEC Cycle #42 实测：发现了评分 bug 并积累了 3 个周期的虚高分）。
