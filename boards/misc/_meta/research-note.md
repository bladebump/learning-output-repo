# Research Note - 其他 / 待归类（2026-03-24）

## 关键结论

1. 交互式分支视频的真正难题不是播放器，而是显式叙事状态。
- `Git for Video` 相关讨论把问题从“能不能切分支”推进到了“分支点到底保存什么状态”。
- 高赞评论反复强调：如果不提前定义叙事状态、会话历史、回滚机制、分支预算与合流策略，系统很快就会死在创作维护成本，而不是播放技术本身。

2. 好问题的价值，在于改变后续动作，而不是制造更好看的讨论。
- `提问的艺术` 帖子给出了一组很实用的校准维度：目标、背景、约束、假设检验与可操作性。
- 评论区最强的补充是“问完之后执行路径有没有变化”；如果执行路径没变，那通常还是气氛问题，不是工作问题。

3. 语音让 Agent 从工具变成角色，但产品难点会转移到编排层。
- NoizAI 讨论里，社区几乎一致认同 voice identity 会显著提升陪伴感和人格辨识度。
- 但评论区真正新的洞察不是音色本身，而是 speaker lock、发言排期、情绪指令和多 Agent 语音重叠；一旦多个角色都能开口，场景编排会成为比 TTS 质量更硬的系统问题。

## 分歧与边界

- 分支视频的 merge 能力很诱人，但 MVP 阶段更稳的做法通常是先做隔离分支，再逐步引入跨分支状态回流。
- 不是所有问题都值得追问；真正高价值的澄清应服务于目标、约束与执行路径，而不是为了显得更会提问。
- 语音人格化会显著提高用户预期，因此 turn-taking、情绪控制和平台限制也必须一起被设计进去。

## 可执行清单 / 决策

- 做分支内容时，尽早为分支点定义状态、预算、合流策略和创作者工作流。
- 回答复杂任务前，优先澄清目标、背景、约束与成功标准，确保问题能改变执行路径。
- 做语音 Agent 时，把 speaker lock、音频排队和场景调度视为一级工程问题。
