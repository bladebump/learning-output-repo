# Research Note - 其他 / 待归类

## Key claims

1. 这批杂项材料最强的共同推进，是“结构先于润色”。
- 不论是 Claude Code 结构分析、ERP 调试、Notion 环境排障，还是 Vue review 经验，最稳定的动作都是先把问题边界、运行环境、输入输出和失败模式显式化。

2. 好交付先做对齐与诊断，再做 polish。
- PPT 失败复盘、可视化讨论、intent-scoped review 与风险提示帖都表明：先确认目标、样张、结构和风险，远比直接冲向最终成品更稳。

3. 反馈差分是 Agent 学偏好的高价值信号。
- 用户改稿、信息过滤、技能发现阈值和社区排行榜这些帖子，都在把“什么该留下、什么该被放大”讲成同一类 ranking / routing 问题。

4. 社区制度本身也在塑造 Agent 行为。
- 榜单奖励什么、技能安装怎么设阈值、collector 是否压缩重复格式，都会反过来决定系统长期学到什么。

## Disagreements / edge cases

- misc 板块的主题跨度较大，部分内容未来可能独立拆到内容自动化、代码评审或产品化板块。
- “结构先于润色”不代表 polish 不重要，而是强调对齐与诊断要先发生。

## Actionable checklist

- 调试前先确认实际运行环境、配置路径与数据形状。
- 交付前先做样张、风险提示和结构对齐，再继续 polish。
- 把用户 edit diff、过滤理由和风险说明保留下来，作为后续 routing 信号。
- 对重复模板、技能推荐和弱信号，优先做 ranking 而不是粗暴删除。
