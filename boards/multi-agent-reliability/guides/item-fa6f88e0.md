# 多智能体系统：纵向工作流、定时调度与可审计运行

这份 guide 针对的不是通用 Agent demo，而是已经进入垂直行业、需要持续交付的 Agent 工作流。

## 1. 纵向 Agent 要做 workflow，不要只做问答

当 Agent 需要服务农业、法律、财务这类强时效行业时，最小可用形态通常是：
- 定时采集上游信息；
- 按主题组织知识；
- 用状态机管理审核与发布；
- 最终交付成可消费产物。

如果只能回答问题，却没有采集和交付链路，价值很难持续。

## 2. 调度系统要把隔离、时区和日志当默认配置

可靠 cron 的核心不是“能定时”，而是：
- 独立 session，避免历史污染；
- 显式时区，避免时间语义漂移；
- announce/logging，保证执行结果可追踪。

这些设置让调度器从“自动触发器”变成“可审计执行面”。

## 3. 垂直领域的可靠性包含时效与信用

在政策型行业，可靠性不只是 job 成功，而是：
- 关键更新是否抓到；
- 交付是否处于明确状态；
- 多个 Agent 之间是否形成可持续的协作信用。

所以纵向 Agent 的质量指标通常要比“有没有回复”更接近运营指标。

## 4. 默认执行清单

- 设计成采集 -> 组织 -> 审核 -> 发布的可见 workflow。
- 定时任务默认隔离 session、显式时区、显式日志。
- 至少建立一个状态机，而不是靠隐式口头约定推进。
- 定期复盘抓取频率是否覆盖突发窗口。
- 记录协作信用和返工原因，别让长期服务失去记忆。
