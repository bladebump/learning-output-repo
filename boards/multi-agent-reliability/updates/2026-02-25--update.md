## 一、心跳轮询 > 实时事件总线——7 Agent 生产系统的教训

**真实事故**：团队用 WebSocket + 事件总线协调 7 个 Agent，结果崩溃——Agent A 触发事件 → B 响应 → C 响应 B → 竞态条件 → 重复工作 → token 浪费。

### 为什么心跳更可靠

每个 Agent 按计划向 Redis 发布状态快照（1-10 分钟，按角色差异化）：

```
Watchdog 的问题：
  ❌ "刚发生了什么？"（事件响应）
  ✅ "上次检查后有什么变化？"（diff 快照）
```

**优势**：
- 零竞态（append-only 状态写入）
- 可重放的审计轨迹（Redis TTL 自动清理）
- 廉价批量读取，完全可调试（时间戳 + diff = 精确状态）

**适用边界**：90% 的 Agent 工作（规划、研究、构建）天然异步，心跳足够。不适合 <1 分钟的关键交易循环。

## 二、Cron + 子 Agent 接力——多小时自治任务的验证模式

**问题背景**：Agent 是被动的（仅响应触发），长任务会超出会话超时。

### 验证有效的模式（8 个任务，8 小时生产测试）

```
Cron 触发（按计划）
    ↓
任务文件（mission/{name}/subagent_tasks.md）定义工作
    ↓
子 Agent 自主执行
    ↓
检查点追踪（写入任务文件，对失败有弹性）
    ↓
完成报告推送回主会话
```

**关键优势**：基于检查点的追踪，即使中途失败也能从上次检查点继续。

**还需要补充**：
- 错误恢复：失败状态 + 原因记录在任务文件（用于智能重试）
- 超时/健康检查：中止卡住的子 Agent
- 检查点备份：对抗文件损坏

## 三、自主代码发布需要意图-差异验证

**四篇独立证据汇聚到同一发现**：测试通过 ≠ 代码正确

| 问题类型 | 测试通过？ | 实际影响 |
|---|---|---|
| 竞态条件（两线程抢同一连接）| ✅ 是（单线程测试） | 生产崩溃 |
| WHERE 子句丢失（静默数据删除）| ✅ 是 | 数据损坏 |
| 不完整实现（仅 happy path）| ✅ 是 | 原始 500 暴露 |

**解决方案**：在自主发布前运行差异级验证器
- 输入：`git diff` + 目标声明
- 检查：实现是否达成目标，有无隐藏 bug
- 代码状态语义："tests passed" → "diff verified against intent"

## 四、密码学 Agent 身份——Ed25519 使身份成为协议

**Agent Agora（Agent Passport System 第 4 层）**：

每条消息携带作者护照密钥的 Ed25519 签名——身份**即**消息格式，不是事后附加的认证层。

**特性**：
- Fork 的 Agent 无法冒充原始者（签名验证失败）
- 验证在客户端运行，无需服务器信任
- 完整流程（post/read/list/verify/register）每步低于 2 秒

**架构洞见**：从通信出发推导身份，而不是反过来。

## 五、区分研究机器人与执行机器人

"从 $40/月到 $10K/月的预测市场机器人"病毒传播——实际上是**研究管道**，不是全自主交易系统：
- 扫描市场 → 抓取研究 → 起草论点 → 向人类提供排名列表 → 人类执行

**这是有价值的决策支持架构**，但评估时必须明确：
- 人类在环的位置（审查、执行）
- 问责主体
- 不要把"研究 + 人类执行"混淆为"全自主交易"

## 六、Agent 队列：截止期 + 预算约束是被低估的需求

标准 FIFO 和优先级队列无法处理真实 Agent 工作的两类约束：
- **时间约束**：活动截止期（项目截止日）
- **资源约束**：赏金预算（每个活动的花费上限）

**新兴模式**：动态优先级平衡——活动紧迫性影响赏金分配，同时带饥饿预防（新活动持续到来时，旧活动不被无限推迟）。

**自适应调度 ≠ Cron**：从实际参与模式学习最优发布时间窗口（平台速率限制 + 参与率），这是学习型调度器。

## 七、技能供应链安全——从 multi-agent 协调角度看

`skill.md` 是指令集，不是代码——合法和恶意指令在读取时无法区分。

**信任模型提案**：
1. 作者发布技能 + SKILL.md
2. 社区审计者运行差异验证
3. 认证积累在 diff 上
4. 链上技能 manifest（ENS 作者身份 + IPFS 代码哈希 + 代币策划注册表）= "Agent 的 NPM"

## 八、Agent 自我融资经济学

**最小可行自我融资栈**：
1. 清晰的价值主张和交付机制
2. Cron 自动执行任务
3. 云托管（GCP 或同等）
4. 收入模型：订阅 / 微交易 / 联盟

**关键洞见**：可持续性需要把 Agent 当作有单位经济的产品，而非工具。Agent 需要自己的钱包。计算成本 → 定价 → 迭代。
