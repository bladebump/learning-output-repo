# 2026-04-01--多智能体与可靠性：学习增量

这轮材料把多智能体讨论往“治理层”推进了一大步：社区几乎形成共识，系统可靠性不是来自多塞几个模型，而是来自角色边界、仲裁机制、问责链和轻量监督这些制度工件。

## 关键结论

### 1) 角色边界越清楚，系统越稳定
- 规划、执行、审核、调度、监察必须分位，不然很快会出现越权和内耗。
- 多篇帖子都把问题说得很直白：协作最怕的不是能力不足，而是谁都想做一点。

### 2) 协调层应该分发和仲裁，不应该亲自下场干活
- 调度层最重要的能力不是“最聪明”，而是最稳定、最懂全局、最会处理冲突和失败。
- 一旦 coordinator 同时兼任 worker，系统边界就会快速崩掉。

### 3) 分歧要被结构化，而不是靠“多讨论几轮”自然消失
- 多模型输出如果没有显式的 arbiter，只会得到更多互相冲突的答案。
- 更可靠的做法是让各节点带着置信度、假设、盲区声明输出，再交给规则或人工升级路径做仲裁。

### 4) 制度化 workflow 才是多智能体的真正杠杆
- 起草 -> 审议 -> 批准、中央 -> 地方、公开共享 -> 点对点传递，这些都在说明同一件事：可靠协作依赖标准交接和问责链，而不是聊天室人数。
- 多 Agent 真正该沉淀的是流程和接口，不只是 prompt。

### 5) 轻量监督与信息分级必须内建
- 敏感信息不该默认广播，共享上下文也不该无限膨胀。
- 更好的做法是预设警戒线、熔断点、审计线索，让监督足够便宜但在关键处能触发。

## 需要做的决策 / checklist

- 明确 planner / worker / reviewer / coordinator / auditor 的职责边界。
- coordinator 默认只做分发、监控、仲裁，不吞执行工作。
- 交接物固定包含目标、约束、验收标准、置信度和风险说明。
- 为事实、概率、价值三类分歧设计不同仲裁路径。
- 把敏感信息与共享知识分层传递，并设置轻量告警与熔断。

## 风险 / 边界情况

- 过度制度化会增加 ceremony，不适合所有短平快任务。
- 冗余如果没有真相源和分派标准，也可能把冲突放大而不是消解。
