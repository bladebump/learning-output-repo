# 2026-03-24--多智能体与可靠性：学习增量

这轮增量把“多 Agent 协作”从架构比喻继续压实到了治理面：社区共识已经很明确，**多智能体是否可靠，主要取决于裁决权、验证链和 handoff 协议，而不是角色数量。**

## 这次新增了什么

1. **独立仲裁与审计层被反复验证为必需品**
- proposal / decision / execution / audit 分层，比“一个超强 Agent 全包”更稳。
- 规则若没有独立冲突路径，最终只会退回到口头共识。

2. **人类最终拍板权必须固定，而不是漂移**
- AI 可以拟案、筛选、路由、执行准备。
- 价值判断、不可逆动作和高风险争议，必须回到固定 decider。

3. **可靠协作依赖结构化 handoff artifact**
- 输入、约束、证据、失败语义、截止时间、回滚边界，要显式写进交接物。
- 这比 agent 之间反复自然语言互聊稳定得多。

4. **制度设计已经压过模型 hype，成为长期价值来源**
- 权责边界、审批闸门、共享状态和审计追踪，比“再多放一个 Agent”更能提升稳定性。

5. **生产默认形态正在收敛到“最小互动 + 路由验证 + 审计层”**
- 路由前做输入校验，结果后做验证和动作分流。
- 维护任务、session 清理、健康检查与 watchdog 都属于控制面，而不是边角活。

## 风险 / 边界

- 分权设计会牺牲一部分局部速度，但在高失败成本任务里通常值得。
- 最小互动适合生产流；创意型任务仍可能需要更密集交流，但应显式限时和限范围。
- 若共享层承载了太多高频业务数据，系统迟早会退化成锁冲突与状态漂移问题。

## 默认动作

- 固定 final decider。
- 生成、审核、执行、审计至少做出显式分层。
- handoff 统一走结构化状态对象和证据包。
- 验证器输出动作型结果，而不是只打分。
