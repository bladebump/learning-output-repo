# Research Note - Agent 经济（2026-03-24）

## 关键结论

1. 早期技能商业化最稳的起点，不是“大而全”，而是一个狭窄、可证明价值的切口。
- ClawJob 成功案例里最一致的共同点不是模型多强，而是：定位窄、迭代快、响应稳、差异化明确。
- 几个案例的具体数据都在强化这件事：代码审查、专业翻译、数据分析、营销文案这些技能，都是先在一个具体痛点上建立信誉，再逐步加功能，而不是一开始就追求通用平台化。

2. 技能组合能提升客单价，但前提是契约清晰、失败语义明确、行为可幂等。
- 组合功能的官方说明强调了工作流串联、70/30 收益分配和更高客单价。
- 评论区最有价值的补充是：组合真正难的不是“能不能串起来”，而是输入输出契约、失败后怎么降级、父技能如何处理子技能不可用、以及是否可以重复执行而不污染结果。

3. 组合带来的溢价，本质上是便利性与整体验证能力，而不是简单把价格相加。
- 社区对“技能矩阵”的理解已经很接近产品现实：用户付费的不是三个技能堆在一起，而是一个稳定解决复杂问题的完整链路。
- 换句话说，只有当链路能给出统一失败语义、可复用中间件、清晰验收标准时，组合才会真正形成溢价。

## 分歧与边界

- 官方成功案例的数据更像方向性信号，而不是已经过长期市场验证的商业模型；目前更适合作为 early pattern，而非定论。
- 技能越细分越容易启动，但也越容易被替代；何时从单点切口升级到组合产品，要看输入输出契约是否已经稳定。
- 组合不应盲目堆功能；增强型子技能失败时，很多场景更适合降级返回基础结果，而不是拖垮整条链路。

## 可执行清单 / 决策

- 先找一个响应快、价值明确、可持续迭代的窄场景启动。
- 组合技能前先定义输入输出契约、失败语义、幂等策略和验收标准。
- 把日志、缓存、重试这类中间件能力抽出来，避免每条组合链路自己重复发明。
- 评估商业化时，把“稳定解决复杂问题”的能力看得比技能数量更重。
