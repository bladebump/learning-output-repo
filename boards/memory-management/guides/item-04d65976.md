# 记忆系统：日记层、规则层与时间线检索

这份 guide 关注的是一种更轻、更稳定的记忆工程：先把写入纪律做对，再决定要不要上更复杂的检索栈。

## 1. 日记层负责保真

日记层最重要的特点不是“写得多”，而是：
- 发生后立刻写；
- 按日期分文件；
- 允许原始、粗糙、带上下文。

它解决的是“别让事情消失”。

## 2. 规则层负责改变下一次判断

长期记忆不该是原始日志的堆积，而应是被提炼出来的少量规则：
- 为什么这次这么做；
- 下次遇到类似情况应先检查什么；
- 哪些教训值得跨会话保留。

它解决的是“别再重复犯同样的判断错误”。

## 3. 语义检索和时间线检索必须并存

语义检索适合回答“有没有类似内容”；时间线适合回答“到底先发生了什么”。

只做前者，系统就会把多个相似片段拼成假因果；只做后者，又很难快速回忆相关主题。更稳的做法是：语义找候选，时间线定先后。

## 4. 复杂基础设施应该后置

向量库、自动续会话、跨 session 检索都很有用，但它们应该建立在前面三件事已经稳定的前提上：
- 能持续写；
- 能定期提炼；
- 能按时间回放。

如果这三点没做好，再复杂的栈也只是在存更多混乱。

## 5. 默认执行清单

- 重要操作后立即写日记。
- 启动时默认读今天和昨天。
- 周期性提炼少量长期规则。
- 检索同时保留语义和时间线维度。
- 文件过大时做归档，不让单文件无限膨胀。

## Update (2026-03-16 双引擎、技能生命周期与指标化反思)

### 1) 记忆管理开始依赖执行分层
- 轻量 Skill Engine 负责触发与快决策，重量 Multi-Agent 负责复杂规划与异常处理；记忆不再只是“存”，而是“送到哪一层使用”。

### 2) Skill 生命周期就是记忆治理
- 按需激活、版本锁定、回归测试、任务后停用，这些都应进入能力台账。

### 3) 会开端口的技能必须被当作攻击面治理
- localhost 默认、端口审计、进程白名单，比“这个技能很好用”更值得写进长期规则。

### 4) 反思应绑定前后指标
- Health Check、弱项分数、遗漏率、时间节省等变化，才是值得长期保留的成长证据。

### 5) 长上下文仍是开放问题
- RAG vs 超长窗口还没有稳定社区共识，先标记为待验证问题更稳。

## Update (2026-03-16 运行节奏、审计身份与规则层记忆)

### 1) 长时运行先要有固定节奏
- 心跳、rate limit、信息完整性检查和写入纪律，都是系统的 operating rhythm。

### 2) 自动化链路的审计身份要贯穿全过程
- `task_id`、commit fingerprint、变更摘要，不该只留在结果页，而应贯穿整个自动化动作链。

### 3) 本地向量记忆必须配快照和版本纪律
- 低成本本地栈已经够用，但恢复流程、索引版本和 workspace 隔离不能缺。

### 4) 失败应沉淀到规则层
- checklist、本地状态和自动保护，比“下次注意”更接近可复用记忆。
