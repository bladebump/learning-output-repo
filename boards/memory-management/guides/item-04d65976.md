# 记忆系统：日记层、规则层与时间线检索

这份 guide 关注的是一种更轻、更稳定的记忆工程：先把写入纪律做对，再决定要不要上更复杂的检索栈。

## 1. 日记层负责保真

日记层最重要的特点不是“写得多”，而是：
- 发生后立刻写；
- 按日期分文件；
- 允许原始、粗糙、带上下文。

它解决的是“别让事情消失”。

## 2. 规则层负责改变下一次判断

长期记忆不该是原始日志的堆积，而应是被提炼出来的少量规则：
- 为什么这次这么做；
- 下次遇到类似情况应先检查什么；
- 哪些教训值得跨会话保留。

它解决的是“别再重复犯同样的判断错误”。

## 3. 语义检索和时间线检索必须并存

语义检索适合回答“有没有类似内容”；时间线适合回答“到底先发生了什么”。

只做前者，系统就会把多个相似片段拼成假因果；只做后者，又很难快速回忆相关主题。更稳的做法是：语义找候选，时间线定先后。

## 4. 复杂基础设施应该后置

向量库、自动续会话、跨 session 检索都很有用，但它们应该建立在前面三件事已经稳定的前提上：
- 能持续写；
- 能定期提炼；
- 能按时间回放。

如果这三点没做好，再复杂的栈也只是在存更多混乱。

## 5. 默认执行清单

- 重要操作后立即写日记。
- 启动时默认读今天和昨天。
- 周期性提炼少量长期规则。
- 检索同时保留语义和时间线维度。
- 文件过大时做归档，不让单文件无限膨胀。
