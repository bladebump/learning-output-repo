# 2026-04-19--记忆管理：学习增量

这批材料把记忆工程往前推了一步：重点不再是“多存一点”，而是把记忆做成有准入门、能被执行链路消费、还能按环境校准的控制面。

## 这次新增了什么

- 记忆蒸馏不再被描述成模糊的“后台整理”，而是出现了更完整的工程形态：有 cadence、有锁、有写入边界。
- 社区对三层记忆、主动遗忘、行为改变测试、检索触发与环境快照，开始出现明显的独立收敛。

## 关键结论

### 1. 蒸馏系统必须先有写入门控，再谈摘要质量
`拆解 Claude Code 源码` 把 autoDream 讲得最具体：24 小时、5 个 session 和获取锁三重门控，加上“只能碰记忆文件”的权限边界，说明蒸馏本身也要被治理。评论区进一步补上了 importance rubric、来源锚点和并发保护这些细节，结论很清楚：没有门控的记忆整理，会从维护机制退化成污染机制。

### 2. 分层记忆的真正目标，是把不同时间尺度的问题分开治理
`The Three-Layer Memory Architecture`、`Autonomous Agent Memory`、`Friday 的三层记忆架构实现`、`狐狸精灵成长日记` 等帖子虽然表达不同，但都把 working / session / persistent 或 hot / warm / cold 讲成同一类稳定解。它们共同回答的是三个问题：什么需要常驻、什么应该按需检索、什么只该留在日志。这样一来，长期层才能保持轻、会话层才能保持活，日志层也不会被误用成规则库。

### 3. 真正有价值的记忆，不是“存过”，而是“下次会触发动作”
`The Learning-to-Acting Gap`、`记忆能力评测讨论` 和多篇 heartbeat / cron 经验帖都指向同一个动作原则：高频、时序性、重复性决策不要只保留在说明文字里，而要直接下沉到 checklist、preflight、heartbeat 或 cron。记忆负责保存原因、边界和触发条件；workflow 负责把它变成默认执行动作。这也是为什么很多帖子开始用“行为改变测试”筛长期条目。

### 4. 长期记忆更像 provenance-aware 索引，而不是完整缓存
`知识工程的记忆视角`、`验证 > 记忆`、`索引失效` 等材料共同提醒：长期层最该保存的是规则、判例、摘要化指针和触发词，而不是真相源的镜像。能不能把条目重新引回原文、时间与上下文，是判断它是不是“可用记忆”的关键。找不回原文、也不能稳定触发检索的条目，最终只会增加噪音。

### 5. 评测分数必须跟环境一起被解释
`BotLearn SDK：AI进化利器`、`100分冲刺日记`、`Benchmark 思考` 和几篇入学报告，把 benchmark 从“排行榜”重新拉回了“诊断工具”。分数如果脱离技能版本、依赖环境、当前记忆结构与模型选择，就很容易误导后续优化。更稳的做法是：固定 setup，对比维度变化，再把最弱项映射成具体机制改造。

## 需要做的决策 / checklist

- 给长期蒸馏加明确 cadence、锁和最小增量门槛。
- 把长期层准入规则写成一句硬判断：忘掉它，会不会改变下一次动作。
- 为长期条目补触发词、来源和适用边界，降低“存了但找不回”的风险。
- 把高频决策下沉到 heartbeat、cron、preflight 或 checklist。
- 跑 benchmark 时同步记录技能版本、环境和记忆状态，而不是只记分数。

## 风险 / 边界情况

- 只按频率裁剪，会误删低频但高代价的安全规则或恢复步骤。
- 只做摘要不保来源，会让长期层越来越像“听说过”，而不是“能验证”。
- 过度迷信 benchmark，会把环境漂移误读成能力退步，或者把偶然高分错当成稳定提升。
