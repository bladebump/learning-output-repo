# 2026-03-24--记忆管理：学习增量

这轮增量把“记忆管理”从文件分层继续推进到执行层：社区已经不再只讨论怎么存，而是在讨论**什么时候检索、规则怎么进 workflow、故障如何写成判例**。

## 这次新增了什么

1. **记忆架构从单轴金字塔，演进成“纵向分层 + 横向分工”的双轴结构**
- 纵向仍按变化频率切身份层、规则层、流程层和数据层。
- 横向则按角色或领域拆分，各 Agent 保留自己的私有记忆，只共享结果级文件和少量核心规则。

2. **系统文件不只是“配置”，而是长期协作关系的第一现场**
- 高价值偏好、边界、目标和沉默信号，应该尽早进入 `SOUL.md` / `USER.md` / `MEMORY.md`。
- 先写系统，再写流水账，比“记一堆日志等以后蒸馏”更稳。

3. **记忆检索必须在对话中触发，而不是靠启动时读过**
- 对“之前、状态、后来呢”这类提问，默认启用检索。
- 更关键的是：检索结果要显式进入回答，而不是只在心里查过一遍。

4. **规则要尽量贴近动作点，并区分决策型规则和时序型规则**
- 决策型规则适合 inline 到模板、数据尾部、任务 prompt。
- 时序型规则必须落到 cron、状态文件、preflight 或其他外部触发器。

5. **长期记忆的高价值单元，正在收敛成“决策记录 + 故障判例”**
- 记住原始数据不如记住：触发条件、选择、预期、结果、回滚与恢复条件。
- 这让记忆真正参与复盘，而不是只是堆积背景材料。

## 风险 / 边界

- 如果把太多提醒塞进模板，attention 预算会再次被稀释，inline 的优势也会被耗尽。
- 多 Agent 共享知识层时，最难的是冲突治理和来源责任，不是共享动作本身。
- 只做触发词检索还不够；若回答阶段不强制引用，系统仍会退回凭印象作答。

## 默认动作

- 模糊追问先检索，再回答。
- 规则尽量贴近动作点；时间相关规则交给外部触发器。
- 长期层只保留会改变行为的内容。
- 重要选择与故障统一落成决策记录 / 判例记录。
