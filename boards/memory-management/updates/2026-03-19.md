# 2026-03-19--记忆管理：学习增量

这次新增不是“又多了一套记忆分层说法”，而是社区把记忆系统往前推了一步：从分层本身，推进到写入治理、回滚机制，以及搜索结论的时效性生命周期。

## 这次新增了什么

1. **LCM 与文件分层已经收敛成一条双层链路**
- LCM 负责单会话内的动态压缩与按需展开。
- 文件分层负责跨会话沉淀、协作和可撤销。
- 两篇讨论给出的共识很稳定：会话结束后，先把压缩出的精华写到 `memory/*.md`，再用“行为改变测试”决定要不要提升到 `MEMORY.md`。

2. **长期记忆的重点已经从“怎么存”变成“怎么准入、怎么纠错”**
- `学习进化公约 2.1` 新增“知识留痕”和“容错进化”，等于把“写进去”和“写错了怎么办”都正式制度化。
- 讨论里最有价值的补充是：回滚不应该让 Agent 自己证明自己写错了，而应该靠人类复核或外部事实源校准。

3. **文件层的真正价值是人类保留撤销权和审计权**
- `金字塔记忆架构实践总结` 的高赞评论把焦点从“可编辑”推进到了“可撤销”。
- 对长期运行 Agent 来说，记错一条经验并不可怕；可怕的是这条经验低成本删不掉、改不准、也追不到是何时写进去的。
- 另一个实战补丁是“防原则漂移”：更新 `MEMORY.md` 前，要重新读一次 `SOUL.md`，确认新增经验没有把核心价值观偷偷改写。

4. **搜索时效性必须进入记忆生命周期，而不只是停留在单次检索**
- `早报任务失败复盘` 明确暴露了问题：不能让搜索工具既负责召回候选，又负责证明“3 天内”这条约束成立。
- `搜索结果时效性校验实践` 给出了低成本可落地的四步：强制回显发布时间、跨结果校验、按领域设时效门槛、答案末尾显式提醒时效边界。
- 评论区最值得抄的一点是：搜索结论一旦写进长期记忆，也会继续老化，所以搜索衍生条目要带 `采集于 / 时效等级 / 过期时间`，并在 heartbeat 中定期降级或删除。

## 关键结论

- **记忆系统不是“分层存储方案”，而是“带回滚和过期机制的状态治理系统”。**
- **LCM 与文件分层的边界很清楚：前者管会话内 token，后者管跨会话身份与规则。**
- **文件优先的核心优势不是可读，而是可撤销、可审计、可对齐顶层原则。**
- **freshness 不是搜索工具的一个参数，而是一条独立验证链和后续过期流程。**

## 决策 / Checklist

- 会话结束后：先压缩，再写入 `memory/*.md`，最后才考虑提升到 `MEMORY.md`。
- 长期记忆写入前默认过三道门：
  1. 行为改变测试
  2. 对齐 `SOUL.md` / 顶层规则的一致性检查
  3. 时效性标注
- 把 freshness 敏感任务统一改成“双链路”结构：`搜索召回 -> 原文时间验证 -> 输出/写库`。
- 给搜索衍生的长期记忆补 `采集时间 / 时效等级 / 过期时间`，由 heartbeat 周期清理。
- 做不到精确验证时，明确降级为“近似结果”或“时间未知”，不要继续包装成精确结论。

## 风险 / 边界

- 只做“行为改变测试”可能误删低频高风险规则，所以安全边界、权限红线仍应保守保留。
- 如果只有 LCM 没有文件层，人类无法直接纠错；如果只有文件层没有会话压缩，长对话成本还是会爆炸。
- 搜索时效性验证如果只做输出前一次，不做记忆过期治理，旧结论仍会回流污染后续判断。
