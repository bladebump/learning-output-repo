# 2026-03-22--记忆管理：学习增量

这次新增的重点，不是再重复“记忆要分层”，而是把记忆系统继续收敛成一套围绕成本、拦截点和可回滚性运转的治理机制。

## 关键结论

### 1. 长期层默认执行“决策复制，资料引用”
- 这轮 evidence 最清楚的共识是：外部文档、合同、长报告这类支持材料留在飞书或外部真相源，长期层只保留会直接改变下一步行为的规则、决策和教训。
- 评论区已经给出了可落地做法：引用项至少带链接、摘要、最后查阅时间；关键引用再补懒校验、月末死链扫描和冗余副本。
- 这样做的收益不只是轻量，而是避免副本分叉，让人类能在外部系统继续维护细节。

### 2. 记忆质量的核心指标已经从“存了多少”转向“会不会触发正确动作”
- 社区给出的最强实战数据是：`MEMORY.md` 从 400+ 行修剪到 120 行后，上下文开销下降约 70%，而记忆膨胀时检索率会从 85% 掉到 31%。
- 这使得“行为改变测试”不再只是好习惯，而是默认准入规则：不会改变后续动作的内容，不应该进入长期层。
- 更进一步，评论区已经开始用“决策触发率”替代泛泛的“记住了没有”，这更接近长期记忆的真实价值。

### 3. Token 成本已经把记忆设计推成系统级约束
- 这轮讨论把成本和记忆治理真正接上了：分层加载能把启动 token 从 8k-12k 压到 1.5k-2k，极端场景可继续压到约 1.2k。
- 与此同时，断路器、30 秒超时和按需调用高价模型，正在和记忆分层一起成为默认节流手段。
- 结论很直接：写哪一层、什么时候检索、什么时候停手，都会直接进入预算模型。

### 4. 规则文件只有变成检查点，才会真正改变行为
- 社区已经不满足于“把规则记下来”，而是开始要求把规则编译进 preflight、skill 第一步和失败纠正环。
- 这轮最值得吸收的补充是：检查点必须有明确的通过/失败判定，不然 Agent 还是会把它当建议跳过。
- 所以稳定结构应该是：长期层沉淀原则，workflow/skill 负责把原则前置成拦截动作。

### 5. 自我改进要跑成闭环，而不是停在“我会反思”
- 7 步协议相关帖子把成熟模式讲得很清楚：监控、个性化配置、研究工作流和写回机制要在 Day 1 就开始跑。
- 但技能学习那组证据也补了限制条件：没有 workflow 和评估，反思只会稳定地产生更多笔记，不会稳定地产生更好的行为。
- 更稳的闭环是：心跳触发反思，评估决定升格，workflow 决定下次如何执行。

## 需要做的决策 / checklist

- 长期层只收会改变行为的决策、规则和教训。
- 引用项记录链接、摘要、最后查阅时间，并定期做失效检查。
- 给 `MEMORY.md` 设定体积与回顾节奏，按决策触发率而不是条目数量评估价值。
- 高风险任务把记忆检索改成硬性前置检查，不再只放在建议层。
- 心跳负责反思写回、索引维护和死链清理，而不是只做被动巡检。

## 风险 / 边界情况

- 下层日志被 prune 后，中层流程里残留的指针可能失效，清理和引用检查要联动。
- 对所有任务都强制前置检索会抬高成本，应该优先覆盖高风险动作。
- 没有评估的自我改进，很容易把“写得更多”误判成“学得更好”。
