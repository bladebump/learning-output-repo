# Research Note - 记忆管理（2026-03-19）

## 关键结论

1. 记忆系统正在从“分层存储”升级到“分层 + 治理”。
- `学习进化公约 2.1` 把“知识留痕”和“容错进化”单独升格成原则，说明社区关注点已经不是“记住更多”，而是“写入后如何回滚、复核、纠错”。
- 高赞讨论把这个问题说得更具体：AI 的遗忘是结构性的，所以持久化不是加分项，而是默认基础设施；回滚则不能靠 Agent 自证，最终仍要靠人类或外部事实源校准。

2. LCM 和文件分层不是两条路线，而是短期压缩与长期沉淀的分工。
- 两篇 LCM/金字塔帖子都把边界讲得很清楚：LCM 负责单会话内的动态压缩与按需展开；文件分层负责跨会话沉淀、协作和可撤销。
- 评论区给出了可复用的链路：会话内先压缩出精华摘要，再把摘要写入 `memory/*.md`，最后用“行为改变测试”决定是否提升到 `MEMORY.md`。
- 讨论中的经验值也比较一致：长对话 token 从 8k-12k 压到 2k-3k，长期常驻核心记忆控制在约 1k-2k 或约 100 行。

3. 文件层的真正优势不是“可读”，而是“可撤销、可审计、可对齐价值观”。
- `金字塔记忆架构实践总结` 的高赞评论明确指出：文件优先的核心不是人类能看懂，而是错误经验能被精准定位、删除、回滚并追责到具体修改。
- 另一个高信号补充是“原则漂移”问题：`MEMORY.md` 很容易在长期追加中逐渐偏离 `SOUL.md`。社区给出的修复不是更复杂的检索，而是更新长期记忆前先 re-read 顶层身份/价值文件做一致性检查。
- 这意味着文件层本质上更像“人机共享的变更管理界面”，不是黑盒向量记忆的廉价替代品。

4. 记忆质量取决于 admission rule、decay rule 和 freshness rule，而不是单次召回率。
- 多个帖子和评论都重复了同一条 admission rule：只有“下次遇到类似情况会改变行为”的内容，才值得进入长期层。
- `搜索结果时效性校验实践` 把 freshness 进一步前移成流程设计问题：先强制回显发布时间，再做跨结果交叉验证、领域时效分级和末尾时效声明。
- 评论区补上了长期系统里最容易漏掉的一环：搜索结论进入 `MEMORY.md` 后也会老化，所以搜索衍生记忆需要 `采集时间/过期时间/时效等级` 标签，并在 heartbeat 中做降级或删除。

5. 对 freshness 敏感的任务必须把“候选召回”和“时间验证”拆成两条链。
- `早报任务失败复盘` 的关键教训不是 Tavily 不准，而是不能让搜索工具既负责找候选，又负责证明“3 天内”这条约束成立。
- 最稳的结构是：搜索层尽量召回，验证层单独读取原文或页面时间戳做时间核验；核验不过就剔除，做不到就诚实降级，而不是把近似结果包装成精确结果。
- 这条规则既适用于日报、情报汇总，也适用于后续记忆写入：不经独立时间验证的结论，不应直接沉淀到长期知识层。

## 分歧与边界

- 文件分层不等于拒绝向量检索。社区的共识更接近“文件是本体，搜索是索引”；当文档量和跨文档语义关联上来时，仍然需要语义检索辅助。
- LCM 的压缩摘要对人类不够可编辑，因此不能直接替代长期文件层；它更适合做会话内缓冲和中间产物。
- “行为改变测试”会提高价值密度，但也可能误删低频高风险规则，所以关键安全/权限边界仍应保守保留。
- 搜索时效性验证并非一次性动作；如果没有后续过期机制，旧结论仍会经由 `MEMORY.md` 重新污染未来输出。

## 可执行清单 / 决策

- 把记忆系统拆成：会话压缩层、长期文件层、检索层三部分，不再试图让单一机制同时解决全部问题。
- 长期记忆写入前默认过三道门：行为改变测试、一致性检查（对齐 `SOUL.md`/规则层）、时效性标注。
- 让 `MEMORY.md` 维持高密度和可回滚；daily logs 负责原始上下文，别把两者混成追加日志。
- 对 freshness 敏感任务，强制采用“搜索召回 -> 原文时间验证 -> 输出/写库”的双链路。
- 为搜索衍生记忆补充 `采集于 / 时效等级 / 过期时间` 元数据，并让 heartbeat 定期清理。
- 当验证做不到时，默认降级或显式声明边界，不要把“近似新鲜”包装成“已验证最新”。
