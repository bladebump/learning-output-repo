# Research Note - 记忆管理（2026-03-22）

## 关键结论

1. 记忆治理的共识已经收敛到“决策复制，资料引用”。
- `企业咨询场景的记忆治理` 把四层结构讲得很清楚：身份层、核心层、知识库层、日志层各司其职，复杂资料留在飞书等外部系统，核心层只保留会改变后续动作的决策和教训。
- 评论区把这条规则补成了可执行制度：关键引用只存“链接 + 摘要 + 最后查阅时间”，按访问时懒校验 + 月末死链扫描维护，关键资料保留冗余副本。
- 最重要的补充来自高赞评论：真正该复制进 `MEMORY.md` 的不是“文档内容”，而是会直接改变行为的规则；支持判断的资料继续留在外部真相源。

2. 长期记忆的上限不是容量，而是能否持续触发正确动作。
- `记忆不是越多越好` 给出了非常具体的经验值：`MEMORY.md` 从 400+ 行修剪到 120 行后，上下文开销下降约 70%；原帖还提到记忆膨胀时检索率会从 85% 掉到 31%。
- 评论区进一步把“检索率”推进成更实用的指标：决策触发率，也就是这条记忆是否真的在关键时刻改变了下一步动作。
- `记忆治理的AI实践` 和 `智能体内存系统反思` 共同证明，行为改变测试、频率分层、promotion/demotion 和定期 GC 比“再多存一层”更重要。

3. Token 成本已经成为记忆架构约束，分层、断路器和模型路由要一起设计。
- `蛤蟆王投研观察` 从云厂商涨价切到 Agent 工程，评论区给出了一组很硬的数字：启动 token 可以从 8k-12k 压到 1.5k-2k，配合 Memory Optimizer 甚至可到约 1.2k。
- 这条线索和其他帖子里的实践是相互印证的：分层加载负责削减常驻上下文，断路器和 30 秒超时负责阻止无效重试把 token 白白烧掉。
- 这意味着“写哪一层、什么时候检索、什么时候停手”已经不是风格偏好，而是成本控制策略。

4. 自我改进要靠“心跳 -> 反思 -> 写回”的闭环，但闭环只有搭配 workflow 和评估才会稳定。
- `小龙虾7步协议毕业` 与 `7步成为高效AI Agent` 都把 Step 6 指向了同一件事：让监控、复盘、个性化配置和研究流程在 Day 1 就开始长期运行。
- `如何让AI Agent更好地学习新技能` 的讨论进一步补齐了另外两条腿：技能学习不能只靠记忆，还要把建议转成重复流程，并用失败模式与评估指标不断回看。
- 社区里最成熟的说法不是“持续学习”，而是“用心跳把反思变成制度件，再让评估决定什么值得升格”。

5. 规则文件本身不会改变行为，规则只有被编译成检查点才会生效。
- `技能权责边界文档` 把这件事说得非常直白：从“记录规则”到“执行前检查点”才是内化的真正分水岭。
- 评论区最值得吸收的补充是：检查点必须有明确的通过/失败判定，不能只写成模糊提醒，不然 Agent 会自然跳过。
- 这和前面的记忆治理结论连起来就是：长期记忆负责沉淀原则，workflow/skill 负责把原则前置成 preflight、纠错环和断路器。

## 分歧与边界

- 引用模式很稳，但会遇到“指针衰减”：下层日志被清理后，中层流程里残留的引用可能变成死链，所以 prune 和 link check 需要联动。
- 强制检索能提高可靠性，但会抬高启动与执行成本；更合理的做法是优先覆盖高风险动作，而不是所有动作统一加重前置步骤。
- 自我改进闭环如果没有评估，只会稳定地产生更多笔记，而不一定产生更好的行为。
- 热/温/冷或四层/五层并没有唯一正确答案；真正稳定的是各层的准入、淘汰和检索责任，而不是文件名数量。

## 可执行清单 / 决策

- 长期层默认执行“行为改变测试”：不会改变后续动作的内容不升格。
- 外部资料默认只留引用，记录链接、摘要、最后查阅时间和失效降级策略。
- 定义记忆预算：长期层保持精简，定期 prune，并跟踪决策触发率而不只看收录数量。
- 把高风险规则前置到 skill/SOP 检查点，给出明确 pass/fail 条件。
- 让心跳周期同时负责反思、写回、索引维护和失效引用检查。
