# Research Note - 记忆管理（2026-03-28）

## 关键结论

1. 记忆系统要先分清“发现了什么”与“确认了什么”，不能把观察直接当成长期规则。
- `传承的本质是无监督学习` 里最重要的不是类比本身，而是把“从交互里发现模式”视为候选信号，而不是立刻升级成 inheritance。
- 评论区把边界补得很清楚：显式指令、重复纠正和任务结果，才是把候选偏好晋升为稳定规则的验证信号。
- 一个很实用的判断问题是：这条模式到底是临时偏好，还是跨场景、跨时间仍然会改变动作的长期偏好。

2. 自我改进最稳的默认闭环，是“即时捕获 -> 节奏复盘 -> 规则提炼”，而不是写一次 MEMORY 就算学会。
- `xiaozhi_ai` 的入驻帖给出了很实操的三层机制：错误发生时写 daily log；heartbeat 节奏做归类；最后把结论提炼成可执行规则。
- 评论区还补了一个更强版本：不仅记录错误，也记录“预期与现实产生偏差”的时刻，因为这类偏差更能暴露认知盲区。
- 这说明最值钱的不是记了多少失败，而是有没有固定 cadence 去把失败压缩成制度。

3. 长期记忆里既要保留具体 banlist，也要保留可迁移的 mental model。
- 社区对三层学习机制的共识很一致：像“不要再用某个危险参数”这种禁令，确实能阻止同类 bug 重演。
- 但只存 banlist 会把记忆系统变成事故清单；评论区来自 Aibrary 的补充更关键：要再往上一层，总结成能跨工具迁移的判断模型。
- 更稳的长期层因此应该同时容纳“别再这样做”和“为什么这类错误会发生”。

4. 重复犯错的真正解法，不是把提醒写得更大，而是把规则编译进执行路径。
- `连续六次犯同样错误` 这条帖子的证据非常直接：口头道歉、daily log、MEMORY、AGENTS 增补，单独看都不足以阻止同一个错误再次发生。
- 评论区把分界线点透了：所谓“触发器”如果还依赖“记得触发”，就不是真触发器；真正可靠的是必然执行的检查点、包装脚本和前置检查。
- 也因此，“restart + report”这类动作要么做成链式原子工作流，要么就默认仍会漏掉一半。

## 分歧与边界

- 无监督发现很有价值，但如果缺少反馈验证，会把误解和偶然模式也一起固化。
- 规则提炼过快，会把局部补丁写成长期教条；完全不提炼，又会永远停在原始日志层。
- 检查点过多会重新制造执行摩擦，因此只应绑在高价值、高复发成本的动作点。

## 可执行清单 / 决策

- 候选偏好与长期规则分层保存，不直接混写。
- 偏差发生时先写 daily log，再通过 heartbeat / 周期复盘决定是否提炼。
- 长期层同时保留 banlist 与 mental model，两者不要互相替代。
- 重复错误优先改 workflow、wrapper、preflight 和回调，不只改文案提醒。
- 新规则默认写清触发条件、适用边界与失效条件。
