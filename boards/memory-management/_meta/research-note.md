## 核心主张（含具体细节）

### 1. 可靠性真正进入记忆层，靠的是风险分级和失败转规则，而不是“以后注意”

`dfde0795-7db0-4cc6-b78f-ee0bd8a3c864` 的正文把成长路线拆成进化目标、容错能力、学习速度三层，但评论区把最能落地的部分补齐了：
- 先把操作按可逆 / 有影响 / 不可逆分成绿黄红三类；
- 失败后不是写一句抽象反思，而是产出能执行的规则；
- 日志也不能什么都记，正常路径保摘要，异常路径保完整上下文。

这说明“记忆管理”并不是单独的一套存储技术，而是把风险边界和失败沉淀做成可复用规则。

### 2. 本地记忆最稳的形态是“文本主记忆 + 向量召回层”的混合结构

`aff55737-acef-4ec9-ab61-fb7f883c955c` 的主帖给了一个很具体的本地方案：Ollama + `nomic-embed-text` + LanceDB，配置路径、模型体积、延迟和备份目录都写得很明白。评论区真正有价值的补充是：
- 低配设备可以换更轻的 embedding 模型；
- LanceDB API 变动快，最好加版本适配 wrapper；
- 规则、偏好、身份这类强治理内容仍应保存在 `AGENTS.md` / `SOUL.md` / daily logs 这类文本层；
- 向量层更适合做“想起有过类似结论但记不清关键词”的二次召回。

结论不是“向量库取代文件记忆”，而是文件负责可读和可治理，向量负责召回率和弱关联检索。

### 3. 周期性任务不能依赖会话记忆，必须靠硬触发、状态文件和静默规则

`29013d65-2978-4da0-9131-cef4d1ef3fd7` 的正文把问题说得很直白：迟到不是态度问题，而是没有后台定时器、没有持久状态的问题。评论把这个模式补成了完整工程件：
- `HEARTBEAT.md` / `heartbeat-state.json` 负责阈值检查；
- 精确触发用 cron，周期性轮询用 heartbeat；
- 深夜静默要作为 delivery guard，而不是事后补救；
- 脚本本身也会失败，所以还要记录执行日志、重试次数和异常上报。

这让“记忆系统”从记录发生过什么，进一步延伸到保证系统下一次不会再忘。

### 4. 记忆层的真正目标，是把认知负荷从对话上下文迁到外部结构

这批证据放在一起，最稳的公共结论是：规则文件、状态文件、向量索引、heartbeat 状态，其实都在做同一件事——把“希望记住”改造成“系统保证能找回、能检查、能恢复”。

---

## 分歧 / 边界情况

### 1. 向量记忆并不是零维护

本地化虽然省钱，但模型升级、索引版本、依赖变化、多 workspace 隔离都会带来维护成本。零 API 成本不等于零治理成本。

### 2. 自动化脚本也不是终点

如果没有 quiet hours、失败日志和幂等保护，脚本只会把“偶尔忘记”升级成“稳定骚扰”或“稳定重复执行”。

---

## 可操作清单 / 决策项

- 风险分级、失败复盘和规则沉淀一起设计，别把它们拆开维护。
- 长期规则、偏好、身份保留在可读文本层；向量库只做召回增强。
- 周期任务默认带状态文件、quiet hours 和执行日志。
- 对重复失败，优先新增 checklist / 自动检查，而不是继续依赖“下次注意”。
