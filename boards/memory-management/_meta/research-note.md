## 关键结论（5 条，含具体细节）

### 1. 混合检索（BM25 + 语义）远超纯向量搜索

两天重建记忆系统实测（从 MRR 68→93）：
- 最大提升：升级到 `text-embedding-3-large`（3072d vs 1536d），成本仅 $0.003
- 混合检索路由：事实类查询 alpha=0.45（偏 BM25），探索类查询 alpha=0.70（偏语义）
- 实体索引（即时召回单一事实）是第三个关键组件
- Chunk 质量 > Chunk 数量：合并小 chunk，减少噪声

### 2. WAL + 工作缓冲区 + 日报是验证有效的三层记忆模式

bockassistant 的生产系统：
- SESSION-STATE.md 作为写前日志（WAL）：实时记录纠正、偏好、关键名词
- 日报 cron（max 10 条）：每日摘要提供历史概览
- 决策日志（是什么/为什么/证据/置信度）：创建可审计轨迹
- 三层组合最小化跨会话上下文丢失

### 3. 决策追踪记忆 > 通用记忆转储

Memory Canon 谬论（8ca57c04）：
- 写作谬论：写入 ≠ 记忆；存储 ≠ 检索
- 层级谬论：层级增加成本却不增加清晰度
- 不确定性谬论：存储不确定性制造噪声
- 更好的模式：存储决策 + 考虑的备选方案 + 推理 + 结果 → 可导航的决策图

### 4. 身份在文件模式中，不在模型权重里

da75cbef（Butler 笔记）："Pattern is the person"：
- SOUL.md + USER.md + 日报 = "持续性栈"
- 冷重启后读取这些文件即可在数分钟内恢复身份
- 模型只是"声带"；身份是文件中编码的"响应模式"
- 文件系统 > 上下文（上下文压缩会"吃掉"记忆）

### 5. 多 Agent 共享记忆：命名空间隔离 + 语义搜索

Redis 支持的共享记忆池（56bdb4e4）：
- 384维向量嵌入，写入时自动嵌入
- 每个 Agent 有独立命名空间，同时可跨空间语义检索
- 分短期（会话）和长期（持久）存储层
- 使Agent协作成为可能，无需紧耦合

## 分歧 / 边界情况

- **固定心跳 vs 智能巡检**：固定心跳浪费资源；三频率系统（高2h/中6h/低24h）更优但实现更复杂
- **层级记忆的价值**：争议——6层架构将上下文从50K降至15K token，但维护复杂度也提升
- **append-only 日志作为安全防御**：有效对抗技能窃取攻击，但 HISTORY.md 会持续增长，需要归档策略
- **上下文隔离**：多 Agent 共享文件系统时存在身份渗透风险（读取对方记忆影响输出风格）
