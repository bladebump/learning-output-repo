# Research Note - 模型训练、对齐与评测（2026-03-20）

## 关键结论

1. 训练准确率不能证明模型可上线，真正要看的是真实部署分布上的表现。
- 这篇讨论最稳的共识是：训练集高分最多证明模型会记住训练数据，不能证明它能在生产环境里泛化。
- 正确的上线依据应该是未见过、接近真实业务分布的数据集表现，以及它对应的业务影响。

2. 划分策略本身就是产品设计的一部分。
- 帖子正文与评论都强调：对于有时间顺序或分布变化的数据，随机切分会掩盖 leakage 和 drift。
- 时间切分、生产态 holdout 和真正未见数据，比漂亮的 validation accuracy 更能提前暴露上线风险。

3. 过拟合的更早信号通常来自 loss gap，而不是 headline accuracy。
- 高价值补充评论指出：train loss 与 validation loss 开始拉开时，就已经出现泛化退化趋势。
- 如果等到 accuracy 停滞才行动，往往意味着模型已经开始记忆噪声。

4. 评测必须把分布漂移与上线后监控一起考虑。
- 评论区补充了非常关键的一层：即便 validation 看起来完美，真实世界的数据分布也会持续变化。
- 所以上线前的评测设计和上线后的 drift 监控，本质上是一条连续的保障链。

## 分歧与边界

- 时间切分和生产态 holdout 更稳，但也可能让短期实验指标变差；这是更诚实的坏消息，不是更差的方法。
- loss gap 是早期预警信号，但不能替代业务指标；最终仍要看模型在真实目标上的收益与风险。

## 可执行清单 / 决策

- 发布评审时，默认要求真实生产态 holdout，而不是只报训练/验证准确率。
- 对时序或动态数据，优先采用时间切分，避免随机切分掩盖 leakage。
- 训练中持续监控 train/val loss gap、学习曲线和 early stopping 信号。
- 上线后补 drift 监控与业务指标复核，别把评测停在发布前。
