# 模型训练与评测：偏好对齐、指标选择与轻量微调

这份 guide 记录的是一条更实用的主线：把对齐、prompt 迭代、评测和轻量微调放进同一个闭环，而不是分散看待。

## 1. 把 RLHF 理解成偏好学习，而不是神秘增智

最重要的心智模型：
- RLHF 主要学习人类偏好
- 它改变的是输出行为与取舍
- 它不自动等于学到了更多世界知识

迁移到 agent 时，默认落点应是：
- 收集接受 / 拒绝 / 改写请求
- 给行为结果打分
- 优先更新 prompt、memory、tool preference
- 只有在收益明确时才考虑更重的训练步骤

## 2. Prompt engineering 应按训练循环来做

把 prompt 当成小型模型去调：
- 样例 = 训练数据
- 失败样本 = 误差分析材料
- 验证集 = 保底稳定性检查

默认流程：
1. 先做第一版 prompt
2. 用多样样例测试
3. 记录失败模式
4. 修改 prompt 或说明
5. 用保留样例复测，防止过拟合

## 3. 先选指标，再谈优化

指标不是汇报格式，而是目标函数的代理：
- 分类任务优先想 F1 / precision / recall
- 生成任务关注 BLEU / ROUGE 这类生成质量指标
- 摘要任务默认至少看 ROUGE

如果指标错了，后面的 prompt、对齐和微调都会优化错方向。

## 4. 资源受限时的默认训练基线

当前最稳的起手式：
- 学习率调度：warmup + cosine decay
- 适配方法：LoRA
- 评估方式：保留验证集 + 失败样本复盘

为什么这条线值得当默认：
- 翻车率低
- 成本可控
- 迭代速度快
- 便于在真实任务里快速试错

## 5. 训练、评测、部署后修正必须讲同一种语言

稳定系统应形成闭环：
- 训练前：定义任务和指标
- 训练中：收集样例与偏好
- 训练后：离线评测
- 部署后：记录 acceptance / rejection / revision
- 回流：把线上反馈重新变成对齐或 prompt 改进输入

## 6. 默认执行清单

- 做 agent 对齐时，优先收集行为反馈，而不是先碰权重。
- prompt 迭代时保留训练样例、验证样例和失败样例。
- 先决定指标，再决定优化方法。
- 默认从 `warmup + cosine decay + LoRA` 起步。
- 讨论“能力提升”前，先检查评测口径。

## Update (2026-03-18 偏好回路、指标前置与轻量基线)

1) **RLHF 的工程落点是偏好回路**
- 对 agent 来说，更重要的是收集接受/拒绝/改写信号，而不是盲目动权重。

2) **Prompt engineering 应按训练循环治理**
- 多样样例、保留验证集和失败复盘，是比“灵光一现 prompt”更稳的方式。

3) **指标选择就是设计选择**
- 指标先定错，后面所有优化都会偏航。

4) **资源受限时，warmup + cosine + LoRA 是默认基线**
- 这条线便宜、稳、可快速迭代。

5) **训练、评测和线上修正应形成单一闭环**
- 线上反馈不回流，训练就无法真正复利。
