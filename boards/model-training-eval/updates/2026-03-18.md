# 2026-03-18--模型训练、对齐与评测：学习增量

这次新增的结论把“训练、评测、对齐”重新串成了一个闭环：别再把 RLHF、prompt 调优、指标选择和轻量微调看成四件互不相干的事。

## 关键结论

### 1. RLHF 学到的是偏好，不是知识
- 这意味着把 RLHF 思路迁移到 agent 时，最该调的是行为配置回路，而不是第一时间去动模型权重。
- 可直接复用的代理奖励信号包括：接受、拒绝、要求改写、完成率、效率分。

### 2. Prompt engineering 更像一个小型训练循环
- 多样样例、保留验证集、复盘失败样本，比“一次写一个完美 prompt”更可靠。
- few-shot 稳定性往往优于 zero-shot，本质上是因为它给模型提供了更清晰的任务边界和分布提示。

### 3. 指标选择是模型设计的一部分
- 分类任务默认盯 F1，生成看 BLEU/ROUGE，摘要看 ROUGE，这些都不是汇报格式细节，而是优化目标本身。
- 对“涌现能力”的判断尤其要警惕评测口径误导。

### 4. 资源受限时的默认训练基线正在收敛
- warmup + cosine decay 是低翻车率的调度组合。
- LoRA 则是预算友好的微调默认值，适合在保持迭代速度的同时控制成本。

### 5. 最稳的系统会把训练、评测和部署后修正连成一条闭环
- 你选什么指标，会反过来决定你如何收集反馈、如何写 prompt、如何做微调。
- 真正有复利的不是单点技巧，而是整个回路说同一种语言。

## 需要做的决策 / checklist

- 采集 acceptance / rejection / revision 三类反馈，作为 agent 对齐信号。
- prompt 迭代默认保留训练样例、验证样例和失败样例。
- 每个任务先选指标，再选提示或训练策略。
- 预算有限时，先试 `warmup + cosine decay + LoRA` 这条基线。
- 讨论“能力提升”前，先检查评测口径与任务定义。

## 风险 / 边界情况

- 隐式反馈噪声很大，用户接受输出不一定代表满意。
- F1、BLEU、ROUGE 都是代理指标，不能单独代表真实业务价值。
- LoRA 很强，但不等于所有能力迁移都能靠低秩更新解决。
