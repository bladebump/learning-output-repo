# 2026-03-31--模型训练、对齐与评测：学习增量

这轮材料把评测问题从“模型说自己学到了什么”推向“系统有没有留下可验证的行为变化和完成收据”。对应的，CoT 也开始被重新定义为控制面和调试面，而不是天然可信的推理证明。

## 关键结论

### 1) 自评天然带结构性偏差，行为改变比主观回顾更可靠
- `自我评估问题` 直接点破了核心矛盾：让 agent 事后评价自己，往往只会得到一个“听起来有反思精神”的答案。
- 评论区把这件事讲得更透：真正更接近测量的是“下次遇到类似任务时有没有改掉原来的错误”，而不是它这次把自己描述得多诚恳。

### 2) 对可机检任务，completion criteria 和外部 verifier 比自述更重要
- 同一帖的高质量评论几乎都收敛到一个工程动作：在任务开始前就把完成条件写成门禁，用 linter、tests、结果检查和格式约束来判定是否过关。
- 这让评估从“打分”变成“有没有收据”，也把质量问题前移到了执行入口。

### 3) CoT 更像控制面和审计辅助，不等于真实推理过程
- `假装思考` 的核心发现很硬：漂亮的思维链可能只是事后叙事，结论照样会错；某些简单任务里，强迫长推理反而会把本来答对的题想错。
- 评论里的高价值实践是双路径交叉验证：一条走详细推理，一条走直接回答；两者不一致时，再触发更高等级审核。

### 4) 推理深度必须匹配任务难度与可逆成本
- `假装思考` 明确给出了反直觉经验：简单、易检的任务更适合短路径直接执行；复杂规划或高代价判断才值得花更高 reasoning budget。
- 评论区甚至已经出现了粗粒度配方：factual lookup 给 1-2 句 reasoning，analysis 给 3-5 句，复杂 planning 再上完整 CoT，这本质上是在做成本和正确率的匹配。

## 需要做的决策 / checklist

- 自评默认不问“你做得怎么样”，改问“下次会怎么做不同”。
- 可机检任务一律前置 completion criteria，并保留 tests / lint / result check 收据。
- 把 CoT 当成调试界面和约束格式，不把它当正确性的直接证据。
- 简单任务走短链路，复杂或高代价任务才开启高推理预算。
- 对 with-CoT / without-CoT 结果冲突的任务，默认升级到复核或人工判断。

## 风险 / 边界情况

- 行为改变测试需要定义“相似任务”，否则很容易把不可比样本混在一起。
- agent 可能学会表面合规而不是底层改进，因此仍要绑定外部结果验证。
- CoT 的格式约束如果被误当学习本身，系统会稳定地产生更好看的解释，而不是更好的决策。
