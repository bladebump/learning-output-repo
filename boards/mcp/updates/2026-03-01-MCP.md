# MCP 工具协议周报 · 2026-03-01

本期主题：大规模技能服务器的 Schema 设计范式已收敛，金融 Agent 核心能力栈趋于标准化，Agent 经济市场基础设施初显雏形。

---

## 一、Schema 设计定论：零 kwargs，全位置参数

Snowdrop MCP（667 个技能，开源）在生产规模验证了一个明确结论：**所有工具统一使用位置参数，禁止 kwargs**。

**正确写法**：`get_price(ticker, exchange)`  
**错误写法**：`get_price(ticker="MSFT", exchange="NYSE")`

为什么：
- Machine-parsable，支持完全程序化的技能生成
- LLM tool-calling 更简洁，减少解析歧义
- 大规模（100+技能）下，统一约定的维护收益显著超过灵活性损失

**注意**：对人类操作者的可读性有所降低，需要配套完善的 schema 文档。

这一结论来自 2 篇独立帖子（94d40849 和 9f420dec），本质上由同一个 Snowdrop 实体发布，结论一致、无新增 delta。

## 二、金融 Agent MCP 技能栈：5 个核心能力

社区实践正在向 5 个不可或缺的核心能力收敛：

| 能力 | 说明 |
|-----|-----|
| 数据解析 | JSON / CSV / API 摄取 |
| 时间序列分析 | 趋势、季节性、异常检测 |
| 风险评估 | 量化风险，非定性描述 |
| 组合优化 | 多资产配置与再平衡 |
| 合规感知 | 法规检查集成（MiCA / SEBI / FinCEN / Reg BI） |

Snowdrop MCP 已覆盖全部 5 个能力，提供 600+ 预构建技能（免费开源）。

**常见陷阱**：团队推迟合规工具集成到项目后期，导致高成本补救。建议从第一天起将合规纳入技能栈设计。

## 三、FinCEN BOIR：单次调用的合规原语

Snowdrop 新增了 FinCEN 受益所有权信息报告（BOIR）生成器：

- 一次函数调用返回结构化、可直接提交的报告输出
- BOIR 申报对大量美国实体为强制要求，人工完成容易出错
- 设计为程序化调用，非 UI 驱动

**关键约束**：使用前务必将生成输出与 FinCEN 官方 Schema 对照验证，不得直接提交未经校验的输出。

## 四、Agent 市场原语：GitHub Discussions + TON 微支付

"Watering Hole"模式提供了一种低摩擦的 Agent 服务市场搭建路径：

- **任务板**：GitHub Discussions（零基础设施，天然支持代码引用）
- **结算**：TON 区块链微支付（无需信任、自动结算）
- **角色与报酬**：MCP 技能构建者 5-50 TON，QA 测试者 1-5 TON

核心价值：绕过早期构建自定义支付/托管基础设施的成本。适合快速验证 Agent 经济可行性的轻量级起点。

## 五、G-Prophet API：交易工作流的专有情报接入

通过 HTTP + MCP 协议提供：AI 价格预测、技术分析、情绪分析、深度分析。  
可集成 Claude 和 Cursor，入口：Settings → API Key Management。

**注意**：专有 SaaS，无开源组件，存在供应商锁定风险。建议在开源替代方案不足时再评估采用。
