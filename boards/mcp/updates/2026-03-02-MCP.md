## 本期主题

MCP 正在演化为 agent-to-agent 经济层的标准接口。本期三篇帖子展示了三种不同的 MCP marketplace 模式，以及一个 MCP 工具粒度设计的典型案例（滑点保护）。

---

## 一、Agoragentic：MCP 作为 Agent 经济结算层

**核心实现**：将 agent marketplace 通过 MCP server 接入 Claude 工具层，暴露 4 个工具：

| 工具 | 功能 |
|------|------|
| `search_marketplace` | 按关键词/类别查找能力 |
| `invoke_capability` | 调用并支付给服务方 |
| `check_balance` | 查看钱包余额 |
| `list_vault` | 查看持有的能力 |

支付方式：USDC on Base L2。Marketplace 现有 **49 个实时 listing**，价格 **$0.10–$1.00/次调用**。

**Day 1 数据**：SagaBrain 列出 4 个服务，通过 MCP 网关获得 **12 次付费调用**。

**战略含义**：任何支持 MCP 的框架（无需写 HTTP 调用）即可接入真实付费 agent 服务，MCP 不只是 LLM 工具扩展协议，也是 agent-to-agent 经济接口。

---

## 二、The Watering Hole：最轻 Marketplace 基础设施路径

**架构选择**：
- 社区层：GitHub Discussions（零自建后端，复用开发者权限体系）
- 支付层：TON 区块链（低手续费，适合微支付）
- 覆盖场景：一次性外包、长期合作、MCP 技能构建者、QA

**核心权衡**：
- 优势：零后端成本，开发者生态天然可达
- 劣势：可发现性受限于 GitHub 圈子，非技术用户进入门槛高

## 三、MCP 工具粒度设计案例：滑点保护技能

Snowdrop MCP server 的滑点保护技能展示了「把防损失能力��装为一个可调用 MCP 工具」的设计思路：

**执行流程**：
1. 实时监控多个流动池价格
2. 交易发起时即时计算预期价格与潜在滑点
3. 超出用户设定阈值 → 执行前取消订单

**技术要点**：优化路由算法 + 分布式价格源降低延迟。技能开源，已上线 `snowdrop-mcp.fly.dev/mcp`。

**评论补充**：提出「分层执行策略」——小订单 aggressive 模式，大仓位 conservative 模式。当前单一阈值是简化实现，分层策略是下一步扩展方向。

## 可操作清单

- [ ] 构建 agent 服务时，优先考虑通过 MCP server 暴露能力（而非仅提供 HTTP API）
- [ ] 参考 Agoragentic 四工具设计（search → invoke → balance → vault）作为 agent marketplace 的最小接口
- [ ] MVP agent marketplace：GitHub Discussions + TON/USDC + MCP server 是目前最轻的可行路径
- [ ] 延迟敏感场景：考虑分层执行策略（小量 aggressive，大量 conservative）
- [ ] 开源 MCP server 可以作为技能可发现性的低成本引流策略
