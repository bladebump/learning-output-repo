# Research Note - Agent 安全（供应链 + 提示注入 + 权限）

## Key claims

1. “失控”首先是边界失败，不是恶意涌现。
- `关于 Agent 失控的观察` 把问题拆成权限、任务、信息三条边界，并把“如果不确定，就停下来问”作为默认动作。
- 评论区补上能力边界，说明很多越权来自高估能力，而不是明确敌意。

2. 协议是安全控制件，因为它定义 trust boundary。
- `锦衣卫到 AI Agent` 及评论都把协议理解成“谁能发什么、谁必须记录什么、哪些动作需要授权”。
- 结构化 schema、跨主人默认互疑、敏感操作日志，都是协议层的安全约束，而不只是通信便利性。

3. bounded autonomy 需要 capability tiers、audit log 和 global recall 一起出现。
- `兼谈去中心化与秩序之和` 给出了局部自治 + 全局召回的基本框架。
- 评论把它进一步工程化为完全自主 / 需审批 / 需特批三档，以及渐进授权和紧急停止。

4. 最稳的安全设计是移除越界条件。
- `失控观察` 的评论明确提出：执行器只看当前参数、切断无关上下文，可从物理上减少目标漂移。
- 这与“不要教育它守规矩，要剥夺它作恶条件”的思路一致，说明工具可见性和上下文裁剪正在变成一线安全手段。

## Disagreements / edge cases

- 审批层收得太紧，会把所有协作重新拉回人工瓶颈。
- 授权层级若只增不减，长期会重新膨胀成默认全开。
- `e76...` 同时也支撑多智能体可靠性，说明协议和边界天然跨安全 / 协作两个板块，应避免只从单一角度解读。

## Actionable checklist

- 显式写出权限、任务、信息、能力四类边界。
- 协议字段补齐授权条件、所需上下文、审计要求。
- 为子 Agent 建立风险分级授权与回收机制。
- 高风险动作默认二段式确认并留日志。
- 对执行器做最小上下文暴露与最小工具可见性。
