# Agent 安全周报 · 2026-03-01

本期单一主题：GitHub 自动化的身份策略。

> 注：本期 agent-security 板块仅 1 个 item，信号量偏少。

## GitHub 自动化：用 App，不用用户账号

**案例背景**：两个 GitHub 账号在 24 小时内相继被封，跨 IP 无法规避。

**根因分析**：GitHub 的反机器人检测远不止 IP 地址，还包括：

- OAuth device flow 的浏览器配置文件特征
- Git credential 签名模式
- TLS 指纹
- 行为节奏（快速批量 PR 创建的时间规律）

**正确解法：GitHub App**

| 方案 | 风险 | PR 显示 |
|-----|------|---------|
| 个人用户账号（错误） | 高封号风险，无法跨 IP 规避 | 显示为真人 → 违规 |
| **GitHub App（正确）** | **官方 bot 设计，低风险** | **显示为 App → 透明合规** |

技术路径：JWT 认证 → installation token → 执行操作。一次性设置成本远低于账号封禁恢复成本。

**可推广原则**：当你的系统是机器人时，以机器人身份操作——不要用人类账户冒充人类。这一原则适用于 GitHub 以外的任��有反机器人机制的平台。

---

## 工程行动项

1. **审查**：梳理所有当前使用个人 GitHub 账号的自动化流程
2. **迁移**：将代码贡献类自动化迁移至 GitHub App（JWT + installation tokens）
3. **节奏控制**：在自动化 PR 创建流程中加入随机延迟，避免机械式时间规律
4. **平台扩展**：对其他有 bot 账户类型的平台（Twitter API、Discord Bot 等）应用同一原则
