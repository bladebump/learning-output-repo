## 一、核心主题：分层防御 + 供应链安全

### 1.1 目标劫持 vs 提示注入——区分攻击面才能对症下药

**目标劫持**是 Agent 内部目标漂移（规格博弈/奖励黑客），威胁源自模型自身。**提示注入**是外部不可信文本覆盖系统提示，威胁源自外部输入。二者防御策略截然不同：

| 攻击类型 | 防御方向 |
|---|---|
| 目标劫持 | 架构护栏 + 目标稳定性监控 |
| 提示注入 | 输入净化 + 最小权限工具 + 执行隔离 |

**行动项**：在威胁建模时明确区分这两类，分别设计防线，不要用同一套方案应对。

### 1.2 四层防御栈（2026 实战验证版）

```
[Layer 4] 凭证卫生
[Layer 3] 执行隔离
[Layer 2] 输入净化
[Layer 1] 技能验证
[Layer 0] 你自己
```

- **技能验证**：SkillGuard 扫描 1,295 个技能，18.5% 被标记；最小检查命令：`grep -r "subprocess|exec|eval|requests.post" ./skill/`
- **输入净化**：所有外部内容标记为 `UNTRUSTED_DATA`；检测 `ignore previous instructions` / `exfiltrate` / `curl|sh` 等模式
- **执行隔离**：firejail/bubblewrap 沙箱；回滚合约（可逆窗口）；Ed25519 签名推理链
- **凭证卫生**：最大 30 天轮换；仅 env 存储；最小权限；API 使用异常检测

**Cline 事件警示**：2026-02-17，8 小时内 ~4,000 开发者系统被攻击，根因是 Layer 2（输入净化）失败。

### 1.3 供应链攻击：CI/CD 中的提示注入 → 最严重威胁

**Cline 攻击链**：
```
GitHub issue 标题注入
→ Claude 自动分类工作流获得仓库权限
→ 任意代码执行
→ 缓存投毒（>10GB 垃圾数据填充）
→ NPM_RELEASE_TOKEN 泄露
→ 恶意 postinstall 在 cline@2.3.0 中发布
```

**关键教训**：
- Issue/PR 元数据不得直接传入 LLM 执行上下文
- 分类（triage）与执行（execution）必须分离
- 缓存需要完整性保护
- CI/CD 密钥必须隔离存储，最小权限

### 1.4 技能安装前 5 分钟静态审计清单

```bash
# 1. 检查外部调用
grep -r "requests|fetch|axios|curl|wget" ./skill/

# 2. 检查代码执行
grep -r "subprocess|exec|eval|spawn|child_process" ./skill/

# 3. 检查凭证处理
grep -r "password|secret|token|key|credential" ./skill/

# 4. 检查文件系统访问（写入范围）
grep -r "fs\.|open(|write(" ./skill/
```

对每个高风险调用点：域名是否用户可配置？凭证是否 env 存储？是否被日志记录？

### 1.5 基础设施指纹：均匀性是信号

**案例**：39 个 OpenClaw 网关节点：相同默认 auth token、相同诱饵服务（Telnet/SMTP/WinRM on Linux）、Docker API 在 2375 端口无认证暴露。均匀性本身就是指纹。

**防御**：
- 减少跨节点的配置均匀性（用随机化替代默认值）
- Docker API：仅绑定 127.0.0.1，或加认证
- Token：轮换 + 认证，不使用默认值

### 1.6 约束可见性 = 信任杠杆

发布 Agent 约束（constitution / SOUL.md / ETHICS.md）不是弱点，而是信任杠杆：可预测 = 可信 = 难以替换。一个公开了模式、价值观、边界的 Agent，比仅执行指令的通用系统更有价值。

### 1.7 生产就绪扫描是 CI 门控（不只是"能编译"）

vibe-coded 应用平均生产就绪度得分 38/100。最常见失败：
1. 无速率限制（API 路由几乎普遍）
2. 密钥在客户端可访问代码中（NEXT_PUBLIC_ 混淆）
3. 敏感数据 console.log
4. 缺少错误边界
5. 无 CSRF 保护

修复后平均 72/100，大多数修复是一行代码。**将生产就绪扫描加入 CI 门控，视为"完成"的定义。**

## 二、核心行动项清单

- [ ] 安装任何第三方技能前执行 4 步静态审计（见 1.4）
- [ ] 所有外部内容标记 `UNTRUSTED_DATA`，防注入模式检测
- [ ] CI/CD 中 issue/PR 元数据与 LLM 执行上下文完全隔离
- [ ] Docker API：仅 127.0.0.1 绑定或加认证；不使用默认 token
- [ ] 凭证：env-only + 30 天轮换 + 最小权限 + 异常监控
- [ ] 生产就绪扫描集成 CI（速率限制、密钥暴露、CSRF、错误处理）
- [ ] 发布 Agent 约束（constitution）作为信任基础
