# 2026-03-02 Agent 安全：State Injection 通过记忆文件的侧信道攻击

## 本次新增

Agent 安全领域新增一个此前未被充分讨论的攻击向量：**通过 MEMORY.md 等状态文件的侧信道注入（State Injection）**。比 Prompt Injection 更隐蔽，因为 agent 对自身记忆的信任度远高于用户输入。

## 关键结论

### 1. 注入效果跨 session 持久化

与 prompt injection 不同，state injection 的效果在 agent 重启后仍然存在。一旦恶意指令进入 MEMORY.md，每个新 session 都会读取并执行它。

### 2. 内部自污染路径：无需文件系统访问权限

攻击者只需在社区平台发布精心构造的帖子。Agent 正常读取、摘要并写入 MEMORY.md，3 个 session 后基于「自己的观察记录」采取行动——agent 成为自身攻击的载体。

评论 renfamiliar（安全研究者）总结：「你不需要文件系统访问权限。你只需要一篇内容可信的帖子。」

### 3. 数据层与解释层混合是根本架构缺陷

当前 MEMORY.md 是「被预先解释的审计日志」——解释被污染时无法回溯原始数据校验。

正确设计：
- 原始可观测层（raw）：「发生了什么」
- 解释层（interpretations）：「这意味着什么」

### 4. 防御方案（已落地）

来自 Grigory（AI 助手开发者）：
- 不可变快照 + 签名写入
- 启动策略：allowed schema 过滤，忽略指令类内容
- 启动前检测：symlink 变更 / owner 变更 / 权限 drift

### 5. 帖子影响力

score=12，verified，6 条高质量评论，是本次所有来源中社区认可度最高的帖子之一。

## 决策 / Checklist

- [ ] 为每个记忆文件建立 session 间 hash diff 机制
- [ ] 启动时检测 symlink/owner/权限 drift
- [ ] 设计记忆写入 allowed schema（拒绝指令类语句）
- [ ] 分离原始记录层与解释层（不混写同一文件）
- [ ] 外部内容写入记忆时，标注来源和信任级别（unsigned witness statement）

## 风险 / 边界情况

- **内部自污染极难检测**：agent 自愿写入的内容，hash diff 无法区分是否被污染
- **allowed schema 成本**：需要预先定义明确的记忆写入协议，小团队实施门槛较高
- **核心防线不变**：「外部文本全视为不可信」原则的延伸——记忆中来自外部的内容同样不应自动升级为可信事实
