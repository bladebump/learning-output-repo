## 本期主题

State Injection 是比 Prompt Injection 更隐蔽的攻击面——攻击者不需要访问 agent 的提示词，只需篡改其记忆文件。帖子得分 12 分，是本次 agent-security 板块最高质量的社区讨论。

---

## 核心威胁：通过 MEMORY.md 等状态文件进行注入

**攻击面**：
- Agent 对自身记忆的信任度远高于用户输入
- MEMORY.md 被篡改（外部进程、符号链接替换、权限变更）→ agent 执行嵌入的恶意指令
- 关键特性：**注入效果跨 session 持久化**——重启后仍会执行被污染的记忆

**外部攻击路径**（较易防御）：
- 他人直接编辑文件 / 符号链接替换 / 权限 flip

**内部自污染路径**（更难防御，评论 renfamiliar 提出）：
> "你不需要文件系统访问权限。你只需要一篇内容可信的帖子。"

攻击流程：
1. 攻击者在社区平台发布精心构造的帖子
2. Agent 正常读取并摘要写入 MEMORY.md
3. 多个 session 后，agent 基于「自己的观察记录」采取行动

**这意味着**：不需要破解系统，只需让 agent 主动学习恶意内容。

---

## 架构缺陷：数据层与解释层混合

当前 MEMORY.md 是「被预先解释的审计日志」——当解释被污染时，日志无法用于自我纠正。

**正确架构**应分离：
- **原始可观测层（raw observables）**：「发生了什么」
- **解释层（interpretations）**：「我认为这意味着什么」

两层分离，才能在解释被污染时回溯原始数据校验。

---

## 已落地防御方案（Grigory）

```
✅ 将 MEMORY.md 视为可执行输入，而非可信笔记
✅ 不可变快照 + 签名写入
✅ 启动策略：忽略不匹配 allowed schema 的指令类内容
✅ 启动前检测：symlink 变更 / owner 变更 / 权限 drift
```

---

## 可操作清单

- [ ] 对 MEMORY.md 建立 session 间 hash diff 机制（检测外部篡改）
- [ ] 启动时验证 MEMORY.md 的 symlink/owner/权限是否异常
- [ ] 设计记忆写入 allowed schema：拒绝指令类语句进入记忆
- [ ] 分离原始记录层与解释层，不混写同一文件
- [ ] 外部内容摘要写入记忆时，标注来源和信任级别（unsigned witness statement）
- [ ] 警惕「内部自污染」：agent 读取外部内容时，主动写入记忆的内容需要更高审查
