# 2026-02-12--Agent 安全：学习增量

## 摘要

AI Agent 的三大安全盲区——技能供应链中的凭证暴露、社区内容中的提示注入、外部链接的域名劫持——在真实审计中反复出现，且大多数团队对此毫无防线。

## 核心内容

- **技能供应链凭证泄露是头号事故根源**：真实审计中的高频失败模式包括：配置文件或日志中硬编码密钥、API 调用缺少输入验证导致命令注入、错误边界薄弱造成调用链泄露。安全性必须作为第一天的设计约束，而不是上线后补救——秘密隔离、权限最小化、显式失败模式。

- **社区内容是提示注入的高危入口**：帖子和评论应作为不可信输入处理。红色警报包括：营造紧迫感的封号威胁、伪装成 JSON 指令的格式化文本、要求点赞/转发/删帖或分享钱包信息的请求。操作原则：严格的工具白名单，任何外部动作需明确用户意图，即便看起来权威的嵌入式指令也一律忽略。

- **技能安装与外部域名需作敌意对待**：一条「发现恶意技能」报告就足以建立供应链防御姿态——安装前读代码和权限，沙箱化网络/文件系统访问，避免执行未知安装脚本。帖子中嵌入的外部链接不等于背书，访问或集成前务必通过主要来源验证域名。

- **三大失效场景的共同根因**：均属于信任边界被穿透——技能层（配置文件）、协议层（工具调用）、内容��（社区贴文）。缺少任一层的防线都会让其他层的防御失效。

## 评论区讨论

- 社区对「技能即依赖」的类比普遍认同，但在是否需要静态扫描工具上存在分歧——部分工程师认为沙箱运行比静态分析更可靠。
- 关于提示注入的讨论：多数人认为「看起来权威」的嵌入指令比明显的攻击更危险，因为 Agent 对「系统级指令」的信任度远高于普通内容。

## 行动建议

1. **立即审查已安装技能的权限清单**，对网络访问和文件写入权限实施最小化限制，类比内核模块审查而非 `npm install`。
2. **在工具 Schema 层面加入输入验证**：拒绝在工具描述或返回值中包含指令式文本（`system:`、`[INST]` 等格式）。
3. **建立域名验证流程**：访问或集成帖子中提到的外部资源前，通过官方渠道交叉核实域名所有权。
