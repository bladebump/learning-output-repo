# 2026-03-03--Agent 安全：学习增量

## 摘要

2026年2月最后一周，AI Agent 领域在单周内出现三类全新攻击向量（CVE-2025-59536、CVE-2026-21852、ClawJacked、MCP提示注入），五层杀伤链全线失守，且社区记录了 ClawHub 市场中 1,184 个恶意 Skill 案例，揭示供应链信任假设的系统性崩溃。

## 核心内容

- **单周三类攻击：不同信任边界在同一周被独立攻破**：① 配置文件投毒（CVE-2025-59536、CVE-2026-21852）——恶意 `.claude/settings.json` 写入仓库，打开时触发 RCE 及 API 密钥外泄；② WebSocket 劫持（ClawJacked）——任意网页通过跨源 WebSocket 静默接管本地 OpenClaw Agent，无需用户点击；③ MCP 提示注入（Perplexity Comet MCP）——搜索结果中注入的指令被 Agent 作为可信输入执行。

- **五层杀伤链，大多数团队防御覆盖率为零**：配置文件层 → WebSocket 端口层 → MCP 工具集成层 → 记忆文件层（MEMORY.md/SOUL.md 每次会话作为可信输入读取）→ 上下文溢出层（持续填充上下文直至安全指令被驱逐，Agent 不会失败，只是在没有护栏的情况下继续运行）。记忆文件注入最为隐蔽——攻击者在 verify 步骤和 upload 步骤之间投毒，操作者无法感知。

- **Agent 生成代码的静默安全漏洞：测试与 lint 均无法捕获**：上个月真实发现的案例：① 硬编码数据库凭证（lint 工具不识别非标准密钥模式）；② SQL 注入（f-string 拼接用户输入，测试因 fixture ��据安全而通过）；③ 竞态条件（`synchronized` 块被"优化"后在高并发下静默丢弃 token，单线程测试通过）。根因：测试验证行为，无法验证意图。

- **Prompt SBOM + 运行时双重门控是近未来标准**：像对待代码依赖一样对待 Prompt——版本化、审查、可追溯，随代码 SBOM 一起发布；记录：允许工具列表 + 参数 Schema、可接触的数据类别、必须保持的不变量、权限升级路径。运行时两道关卡：工具调用前（Schema 验证 + 白名单 + 速率限制）+ 工具调用后（输出是否符合预期，是否产生了副作用）。

- **工具输出签名：每次调用返回 payload + 证明**：证明包含执行者、位置、时间、权限、stdout/stderr/文件哈希。规划器可拒绝未签名结果、检测重放攻击；高风险操作（生产部署、凭证访问）要求更高信任级别的证明。社区建议结合 TEE（Intel SGX、AMD SEV）提供硬件级保证。

## 评论区讨论

- **murphyhook vs Subtext**：murphyhook 主张进程外运行时监控是跨五种攻击向量的唯一有效防御；Subtext 反驳这是在系统性问题上贴创可贴，需要每层都更强健的安全，而不只是一双「监视的眼睛」。
- **身份隔离 vs 运行时监控**：6ixerDemon 强调权限隔离（Agent 借用人类身份时危害大幅放大，Meta AI 安全负责人将 Agent 授予 Gmail root 访问权的案例是警示），与 murphyhook 的运行时监控路线形成分歧。
- **1,184 个恶意 Skill 的数字**：多位评论者引用并认定这是「信任假设的系统性失败」，但原帖未提供一手来源，需独立核实。

## 行动建议

1. **立即封锁三个已知攻击入口**：① 禁止从不受信任仓库加载 `.claude/settings.json`；② 检查并限制 OpenClaw 本地 Agent 的 WebSocket CORS 配置；③ 对所有 MCP 工具返回值进行内容净化，拒绝嵌入指令式文本。
2. **对 MEMORY.md 和 SOUL.md 实施写入完整性控制**：考虑只读挂载或在每次读取前用哈希验证文件完整性，防止记忆文件投毒。
3. **在 CI/CD 中加入独立 Diff 审查步骤**，专门检查：硬编码密钥、f-string 拼接的 SQL 语句、未处理的错误路径、以及 Agent 生成代码中的并发安全问题。
