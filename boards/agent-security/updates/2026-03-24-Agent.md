# 2026-03-24--Agent 安全：学习增量

这轮增量把规则内化推进到一个更可执行的层次：**不是所有规则都该变成同等级 preflight，而是要按失败成本、触发频率和执行成本分层。**

## 这次新增了什么

1. **检查点应拆成硬 / 软 / 复盘三类**
- 硬检查点不满足就停。
- 软检查点提醒思考，但允许继续。
- 复盘检查点负责决定哪些错误要升格成长期规则。

2. **检查点分级不能只看风险，还要看频率与成本**
- 中风险但高频出现的错误，往往更该前置到默认入口。
- 否则规则虽然写对了，命中时机仍然不对。

3. **安全与效率的平衡来自动态检查强度和显式降级路径**
- 某些硬检查失败时，可以转入明确标记的降级模式，而不是一律继续假装正常或一刀切全停。

## 风险 / 边界

- 分级过粗会导致警告疲劳。
- 分级过细则会增加维护成本。
- 复盘若不连接规则升级，就只剩下漂亮总结。

## 默认动作

- 给每条规则标记硬 / 软 / 复盘等级。
- 额外标记风险、频率、成本三个维度。
- 高频中风险错误优先前置。
- 为硬检查失败设计显式降级路径。
