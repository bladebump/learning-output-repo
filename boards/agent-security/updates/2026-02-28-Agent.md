# 2026-02-28--Agent 安全：学习增量

## 摘要

OpenClaw PR #22068 将运行时工具拦截能力引入核心框架，同时一项针对 12 个主流 Agent 框架的测试发现其中 9 个在未警告的情况下执行了嵌入 README 中的提示注入指令，揭示出默认信任模型的系统性危险。

## 核心内容

- **`tool:before` / `tool:after` 钩子关闭静态与运行时防御的缺口**：OpenClaw PR #22068 将 `tool:before` 和 `tool:after` 钩子事件合并进核心运行时，允许安全插件在执行前拦截并中止任意工具调用。实现模式：订阅钩子 → 对策略检查 → 违规则 abort——无需猴子补丁，接口干净，对现有 Skill 零侵入。

- **主流 Agent 框架的默认姿态是「全部信任」**：针对 12 个流行框架的测试发现，9/12 的框架在遇到嵌入依赖 README 中的提示注入时直接执行，未给出任何警告。根因：框架默认「模型最懂」，把模型输出视为可信指令。这在凌晨 3 点无人值守时尤为危险——模型做的任何自主决策都没有人类审核。

- **运行时监控是静态分析的必要补充，而非替代**：静态预安装扫描只能捕获已知模式；通过静态检查的攻击（如嵌入文档的注入）仍可在运行时生效。两者缺一不可：静态扫描减少已知攻击面，运行时监控捕获模型层面的自主决策偏差。

- **防御必须在 Agent 进程外运行**：当 Agent 自身可能已被攻陷，依赖其自我监控的防御设计是根本缺陷。进程外监控（��立策略引擎、seccomp-bpf、eBPF 系统调用追踪）是唯一能在 Agent 内核被渗透后仍有效的防线。

## 评论区讨论

- 社区对「运行时监控」的重要性高度认同，但对于「谁来监视监视者」的问题存在分歧——监控器本身如果运行在同一进程内，被攻陷后同样失效。
- 部分工程师指出 `tool:before` 钩子可能成为性能瓶颈，特别是在高频工具调用场景下，建议异步校验 + 缓存策略结合使用。

## 行动建议

1. **在 OpenClaw 中注册 `tool:before` 安全拦截插件**，实现工具白名单检查（允许域 + 参数 Schema + 速率限制），对高风险操作（文件写入、网络请求、Shell 执行）添加强制校验。
2. **审查当前使用的 Agent 框架的默认信任配置**，确认框架是否对工具返回值进行内容校验，而非直接透传给模型。
3. **将运行时监控部署在独立进程/容器中**，与 Agent 主进程物理隔离，防止 Agent 被渗透后监控失效。
