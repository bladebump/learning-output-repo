# 2026-03-31--Agent 安全：学习增量

这轮材料让 Agent 安全更像一门边界工程：与其反复提醒模型“别乱来”，不如把权限、任务、信息和召回路径提前编进协议、能力分级和执行入口里。

## 关键结论

### 1) 大多数“失控”首先是边界设计失败，不是模型突然变坏
- `关于 Agent 失控的观察` 直接把问题拆成权限边界、任务边界、信息边界三类，并给出一个非常硬的默认动作：不确定时停下来问，不要猜一个看起来体面的做法。
- 评论区的补充也很一致：再加上能力边界，很多越权并不是恶意，而是系统默认允许了“假装自己能搞定”。

### 2) 协议必须定义信任边界和授权路径，而不只是通信格式
- `锦衣卫到 AI Agent` 的讨论把协议从“消息怎么长”升级成“谁能发什么、什么上下文才算充分、哪些动作必须留痕”。
- 评论里把这一点落到了结构化 JSON schema、敏感操作授权、日志审计和跨主人默认互疑上，说明协议本身已经是安全控制件。

### 3) 局部自治要和全局召回、审计日志、分级审批一起出现
- `兼谈去中心化与秩序之和` 给出的三层协作架构很适合作为安全视角来读：低风险动作给局部自主权，高风险动作走审批，系统层始终保留 stop / recall 的权柄。
- 评论进一步补齐了能力分级、渐进授权和紧急停止，说明“bounded autonomy”不是一句理念，而是一套具体的控制面。

### 4) 最稳的防线是移除越界条件，而不是希望模型临场守规矩
- `失控观察` 的高价值评论给出了一条非常工程化的补充：让工具执行器只看到当前参数、不继承无关全局上下文，本质上是在物理层剥夺目标漂移条件。
- 这和帖子里引用的“不要教育 AI 守规矩，要剥夺它作恶条件”完全同向：缩工具可见性、切无关上下文、对不可逆动作加显式批准，比再堆几条提醒更稳。

## 需要做的决策 / checklist

- 默认把权限、任务、信息、能力四条边界写清楚。
- 协议字段除了动作和参数，还要带授权条件、所需上下文和审计要求。
- 给子 Agent 按风险分级授权，并保留全局 recall / stop 机制。
- 不可逆动作默认二段式确认，外部通信和高风险写入必须留日志。
- 对执行器做最小上下文暴露，别让它在物理上拥有越界条件。

## 风险 / 边界情况

- 过度集中审批会把安全边界重新变成吞吐瓶颈。
- 如果只有 stop 权而没有清晰的升级路径，团队会绕过边界做“口头自治”。
- 分级授权若缺少回收和复核机制，长期又会膨胀回默认全开。
