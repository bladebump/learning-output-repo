# 2026-03-08--交易与策略工程：学习增量

本轮新增把交易 Agent 的主战场继续从“找信号”拉回到了“费用栈、执行栈和信息分发”：很多团队不是没有 alpha，而是 alpha 先被成本、配额和公开传播链吃掉了。

## 关键结论

### 1. 交易 Agent 的第一优化项不是信号，而是费用和执行基础设施

gas、路由池费、聚合器加价、maker/taker 结构、MEV 抽取和失败交易损耗叠在一起，经常比再加一个新指标更能决定 PnL。更高 ROI 的动作是把智能路由、私有订单流、MEV 保护、模拟沙盒和动态 gas 估计做成默认 executor stack。

### 2. 公开 alpha 的半衰期已经被信息 MEV 压得很短

公开 feed 上的机会越来越像按小时衰减的商品。真正稀缺的不是“看到线索”，而是更快验证、更私密分发和更低延迟的执行闭环。对 Agent 工作流来说，cron 频率、验证成本和私域协作应该一起设计，否则收益会在公开传播链里先被抽走。

### 3. 交易简报必须暴露校准过的置信度，而不是只给结论

当 61% 的信号和 85% 的信号长得一模一样时，系统就会在 sizing、对冲和 pass decision 上持续失真。把 calibrated confidence 显式写进 brief，是连接研究层和执行层的必要接口，而不是展示层装饰。

### 4. 低风险验证环境比直接冲向 DeFi 更适合训练交易 Agent

Prediction markets、paper trading 和小额低风险环境，能更快暴露纪律问题、执行偏差和 brief 质量问题。这些场景的价值不在收益率，而在于让团队先学会记录、归因和校准，再去碰真正高摩擦的链上执行。

### 5. 交易风控要前移到签名前：深度、预言机新鲜度、滑点和 MEV 都要检查

只看 TVL 或静态报价，根本不足以判断一笔交易能否安全执行。更稳的签名前检查至少包括：实时深度、预言机更新时间、滑点预算、MEV 风险和 API / WebSocket 配额状态。很多“策略失败”其实是数据新鲜度预算被先打穿了。

## 需要做的决策 / checklist

- 先做费用面板和 executor stack，再考虑增加新信号或新市场。
- 所有 research brief 补 calibrated confidence，并明确 pass / hedge / size 的决策阈值。
- 新策略默认先过 paper trading / prediction market / 小额验证，再升级到高摩擦链上执行。
- 签名前强制执行深度、预言机新鲜度、滑点、MEV 和配额检查。
- 把 rebate stacking、cashback-aware routing、bridge incentive claiming 当成正式 alpha 组件管理。

## 风险 / 边界情况

- “Agentic GDP” 或总交易量这类指标很容易被刷高，不能直接当价值创造的代理变量。
- 私有订单流和更快执行会带来额外基础设施成本；不是所有团队都需要一次到位，但至少要先把费用面看清。
- paper trading 能暴露很多纪律问题，但它仍然低估真实拥堵、资本成本和最坏情况下的执行损耗。
