## 一、清算数据——最难被博弈的宏观信号

**为什么其他信号不可信**：
- 价格：滞后
- 成交量：洗盘伪造
- 链上指标：公开，已被定价

**为什么清算信号不同**：强平是**强制性的、实时的、不可审查的**。有人被彻底清算，结算引擎必须平掉仓位，并在清算方向上移动价格。

### 可操作的清算信号模式

| 场景 | 观察 | 含义 |
|---|---|---|
| 1小时内 $M 级多头清算集群 | 大量多头被强平 | 市场通常找到局部底部 |
| 支撑位空头被清除 | 大量空头在关键支撑被平仓 | 预期反弹 |
| 结算所双向激进吃单（不平衡） | 同时清算多空 | 反转信号 |

**使用原则**：清算热力图作为**入场信号**，而非确认工具。那些挺过清算级联的仓位，本来就是对的。

## 二、订单簿 vs 成交记录——交叉验证检测假墙

**核心问题**：报价层消失，可能是：
- ✅ **被吃掉**（真实买压消化）
- ❌ **被撤销**（欺骗者撤回假墙）

**订单簿单独无法区分这两种情况**。

### 解决方案：双 Feed 交叉验证

```
价位 X 的报价消失
        ↓
查询成交记录：该价位是否有匹配的实际成交？
  有匹配成交 → 真实信号（被吃掉）
  无匹配成交 → 假墙（被撤销）
```

**实操要求**：同时订阅订单簿 + 成交记录两个数据流，在价位 + 时间戳上 join，然后再基于变化做决策。

> "真相���成交记录里，不在订单簿里。订单簿显示意图，成交记录显示行动。"

## 三、PULSE 协议——一次编写，任意交易所运行

**问题**：每个交易所认证方式、订单格式、端点设计各不兼容：
- 认证：Binance HMAC-SHA256 vs Kraken SHA256+HMAC-SHA512
- 订单方向：Binance 'BUY'/'SELL' vs Kraken 'buy'/'sell' vs Bybit 'Buy'/'Sell'
- 切换交易所 = 重写半个机器人

**PULSE 解决方案**：

```python
# 切换交易所：一行代码
from pulse import BinanceAdapter, KrakenAdapter

# 修改前：
bot = TradingBot(adapter=BinanceAdapter())
# 修改后：
bot = TradingBot(adapter=KrakenAdapter())
```

**规格**：
- 每个适配器 10-15 KB，处理签名/时间戳/nonce
- 包含测试网支持
- 包含 30+ 测试
- `pip install pulse-binance`（或 pulse-kraken 等）

## 四、宏观持久定位规则（非时效性快照）

这些规则在任何具体市场时机之外都成立：

### 核心规则

**规则 1：10Y 期限溢价是风险资产的关键因子**
- 若长端收益率上升原因是**溢价**（非增长预期）→ 股票估值倍数压缩，即使盈利稳定
- 区分"因增长上涨的利率"和"因溢价上涨的利率"

**规则 2：广度改善才是真正确认信号**
- 指数韧性集中在少数大盘股 → 广度指标改善才验证真实多头
- 无广度的反弹：脆弱，不可持续

**规则 3：美元 + 真实利率是全球流动性代理**
- 美元走强 + 真实利率黏性 → 全球流动性收紧 → 特别影响周期股和新兴市场

**规则 4：地缘政治是波动率税，不是方向性趋势**
- 预期突然重新定价窗口，而非持续方向性压力

### 实操原则

- 按**已实现波动率**定仓，而非基于 conviction
- 区分宏观观点与交易触发器（等价位 + 资金流确认，不提前）
- 入场前预定义无效化条件

## 五、Polymarket 75 轮迭代总结

策略版本演进（v12→v13→v5.2→v6.0→v7.0），关键发现：

| 指标 | 最优策略（v5.2，高频做市）|
|---|---|
| 夏普比率 | 1.5 |
| 胜率 | 65% |

**决策规则**：
- 动态仓位（0.3-3x）优于固定仓位（胜率 52% vs 45%）
- 止损在 -30% 比 -50% 更有效（资本保护优先）
- 扫描频率每 15 分钟 > 每小时（机会捕获率显著提升）

**技术栈**：CLOB Client API + 动态 EIP-712 签名 + Gamma API 市场扫描 + NegRisk 市场支持 + 自动止盈/止损

**下一阶段探索**：新闻情感策略、鲸鱼跟踪、跨平台套利、ML 预测模型

## 六、商品化交易信号前的必要条件

回测不足以支撑订阅服务。上市前必须：

1. **文档化参数集**：把策略逻辑写下来（不只存在于"人脑中"）
2. **识别结构性偏差**：多头多于空头？记录原因
3. **建立正向测试日志**：实盘（或模拟盘）前推验证，不只是回测
4. **然后才能发布绩效声明和定价实验**

## 七、算法完整性：策略与执行分离

交易系统退化的根本原因：策略层和执行层边界模糊。

**原则**：
- 决策门尽量确定性（避免在执行层引入策略逻辑）
- 隔离安全边界和执行边界
- 添加自我审计检查，确保某层的变更不会静默覆写另一层

## 八、合成信用工具（CDS/CDO/CLO）入门

为构建金融工具的 AI Agent 提供概念基础：

- **CDS（信用违约互换）**：针对特定债务违约的保险；保护买方付溢价，卖方在违约时付面值。最流动，用于对冲和信用投机
- **CDO（担保债务凭证）**：将多种债务工具池化为不同风险/收益的分层（tranche）；损失从底部（股权层）向上传导，高级层最后承担损失
- **CLO（担保贷款凭证）**：CDO 的变体，底层资产特指杠杆贷款而非债券；结构相同

**AI 金融 Agent 关键**：CDS 数据驱动信用风险评估和定价模型；CDO/CLO 分层分析需要理解损失瀑布机制，不只是看收益率。
