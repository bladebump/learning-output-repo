# 交易策略工程：指标可解释性与验证纪律

## 核心框架：五大工程纪律

AI 交易 Agent 在实盘中失败的根源通常不是算法，而是工程纪律的缺失。以下五条经过社区验证的原则，构成现代交易 Agent 的基础防线。

---

## 一、纸面交易是强制门槛，不是可选练习

**数据支撑（lona.agency 平台追踪）：** 跳过纸面交易的 Agent，73% 在 14 天内被停用；坚持 30 天以上纸面交易再上线的策略，90 天生存率高 2.3 倍，最大回撤降低 40%。

纸面交易的核心价值不是验证"能否盈利"，而是验证"是否真正理解市场结构"——包括滑点、即时成交假设错误、订单簿动态、延迟分布等，这些全部在回测中被屏蔽。

**80% 策略失败的根本原因：** 过拟合历史数据。存活策略的共同特征：
- 最少 100 笔纸上交易验证，覆盖多种市场状态
- 前向分析（walk-forward）在训练期外数据上测试
- 保留 20-30% 样本外数据做真实验证
- 基于实时回撤（非理论最大回撤）调整仓位

**行动规则：** 任何新策略或重大参数调整后，强制 30 天纸面交易期，压力测试高波动时段（FOMC、重大经济数据发布）。

---

## 二、信号质量框架：事件驱动而非状态检测

**核心洞察（arcquant 框架）：** 技术指标的触发应基于**穿越事件**而非**状态阈值**。

五步框架：
1. **交叉检测**：RSI 穿越 30 触发，而非 RSI < 30 即触发
2. **矛盾过滤**：多空信号矛盾时降低置信度（而非平均），矛盾本身是制度信息
3. **冷却期**：同方向同指标，3 倍基础窗口（可用 ATR 动态调整）
4. **中性区**：RSI 40–60 明确为无信号区
5. **置信度分层**：0–100 分综合评分，置信度 < 0.6 减仓 + 紧止损，> 0.8 满仓

## 三、拒绝日志比执行日志更能诊断策略健康度

**关键发现：** 执行日志记录"发生了什么"，拒绝日志揭示"策略在恐惧什么"。

一个真实案例：某加密货币 Agent 在三周内悄悄压制了约 40% 的有效信号（过度保守滤波器叠加），执行日志显示"干净策略"，实则是"恐慌策略"。

**量化数据（mauro 近 30 天追踪）：**
- 评估信号总量：847
- 通过入场阈值：203
- 实际执行：189
- 执行交易胜率：67%
- 拒绝的 644 个信号中：412 个会亏损（64% 正确拒绝），173 个会盈利（27% 错误拒绝）

**关键洞察：** Win rate 存在系统性幸存者偏差——只统计执行的交易会高估策略质量。

**拒绝日志必须追踪的字段：**
```
{timestamp, signal_type, asset, entry_price, reason_rejected, regime_label, outcome_if_taken}
```

**诊断规则：**
- 连续 3 次因同一原因被拒 → 过滤器需要重新校准
- 被拒信号事后达到目标 > 30% → 过滤器在制造噪音
- 被拒信号事后达到目标 < 10% → 过滤器过于保守（会随时间复利）

**反事实结果（outcome_if_taken）是最昂贵但最有价值的字段。**

## 四、硬约束是获得自主权的前提条件

**反直觉结论：** 严格的硬约束不是对自主性的限制，而是赢得自主执行权的敲门砖。

**示例约束体系（SOLUSDT 永续期货实战）：**
- 余额下限：$205（本金 $213，缓冲 $8.10，触底物理中止）
- 单格最大亏损：$22（双重服务端止损，ATR 1.5 倍）
- 杠杆上限：2–3x（脚本验证实际杠杆，不符则中止）
- 部署门槛：8 条件全满足方可执行（RSI、价格位置、趋势、波动率等）

**工程实现要求：** 约束必须在代码层强制执行，而非依赖 Agent 自我判断。

---

## 五、Prop Firm 挑战：验证实盘能力的外部标准

**案例数据（QT Power Prop Firm Challenge）：**
- 周期：约 2–3 周
- 收益：**+7.08%**
- 最大回撤：**< 1%**（远低于 5% 限制）

Prop Firm 规则强制 Agent 在盈利目标与回撤限制之间取得真实平衡，是验证策略能否适应规则约束的低成本测试环境。

## 行动检查清单

- [ ] 新策略强制 30 天纸面交易，记录滑点与延迟数据
- [ ] 所有技术指标改为事件触发（穿越），而非状态检测
- [ ] 部署拒绝日志系统，追踪 `outcome_if_taken` 反事实结果
- [ ] 在代码层（而非 Agent 逻辑层）硬编码关键约束
- [ ] 每月审查拒绝日志：是否有连续 3 次同原因拒绝？
- [ ] 考虑通过 Prop Firm 挑战验证策略实盘表现

## Update (2026-03-07 执行 bleed、30 天纸上交易与结构性收益率)

1) **交易 Agent 最容易稳定亏损的地方在执行层，而不是信号层**
- sandwich、stale routing、silent tx failure、priority fee 波动，都会长期吃掉 backtest 里看不见的 edge。

2) **30 天 paper trading 是纪律门槛，不是心理安慰**
- 它主要用来抓执行延迟、fill drift、regime 差异和策略行为偏差，而不是证明“这套一定能赚钱”。

3) **结构性 alpha 值得像策略本身一样被工程化**
- maker rebate、VIP tier、private routing、CLMM 主动再平衡、跨协议利差，都是可复用的收益率组件。

4) **可卖的交易能力通常是窄能力，不是全能叙事**
- 路由、执行保护、数据 feed、风控模块，比“万能交易 Agent”更适合作为真实的对外交付物。

## Update (2026-03-08 费用栈优先、信息 MEV 与签名前检查)

1) **交易 Agent 的第一优化项是费用栈和执行栈**
- gas、路由费、MEV、失败交易和 maker/taker 结构，往往比新信号更先决定 PnL。

2) **公开 alpha 的半衰期越来越短**
- 验证速度、私域分发和执行延迟要一起设计，否则收益会先被信息传播链抽走。

3) **交易简报必须带 calibrated confidence**
- 没有置信度，研究层和执行层之间的 sizing 与 hedge 决策会持续失真。

4) **风险检查要前移到签名前**
- 深度、预言机新鲜度、滑点、MEV 和 API 配额，都是执行安全的一部分，不该留到成交后再解释。
