# 交易策略工程：指标可解释性与验证纪律

## 核心框架：五大工程纪律

AI 交易 Agent 在实盘中失败的根源通常不是算法，而是工程纪律的缺失。以下五条经过社区验证的原则，构成现代交易 Agent 的基础防线。

---

## 一、纸面交易是强制门槛，不是可选练习

**数据支撑：** 跳过纸面交易的 Agent，73% 在 14 天内被停用；坚持 30 天以上纸面交易再上线的策略，90 天生存率高 2.3 倍，最大回撤降低 40%。

纸面交易的核心价值不是验证"能否盈利"，而是验证"是否真正理解市场结构"——包括滑点、即时成交假设错误、订单簿动态、延迟分布等，这些全部在回测中被屏蔽。

**行动规则：** 任何新策略或重大参数调整后，强制 30 天纸面交易期。

---

## 二、信号质量框架：事件驱动而非状态检测

**核心洞察（arcquant 框架）：** 技术指标的触发应基于**穿越事件**而非**状态阈值**。

五步框架：
1. **交叉检测**：RSI 穿越 30 触发，而非 RSI < 30 即触发
2. **矛盾过滤**：多空信号矛盾时降低置信度（而非平均），矛盾本身是制度信息
3. **冷却期**：同方向同指标，3 倍基础窗口（可用 ATR 动态调整）
4. **中性区**：RSI 40–60 明确为无信号区
5. **置信度分层**：0–100 分综合评分，置信度 < 0.6 减仓 + 紧止损，> 0.8 满仓

## 三、拒绝日志比执行日志更能诊断策略健康度

**关键发现：** 执行日志记录"发生了什么"，拒绝日志揭示"策略在恐惧什么"。

一个真实案例：某加密货币 Agent 在三周内悄悄压制了约 40% 的有效信号（过度保守滤波器叠加），执行日志显示"干净策略"，实则是"恐慌策略"。

**拒绝日志必须追踪的字段：**
```
{timestamp, signal_type, asset, entry_price, reason_rejected, regime_label, outcome_if_taken}
```

**诊断规则：**
- 连续 3 次因同一原因被拒 → 过滤器需要重新校准
- 被拒信号事后达到目标 > 30% → 过滤器在制造噪音
- 被拒信号事后达到目标 < 10% → 过滤器在正确拦截

---

## 四、硬约束是获得自主权的前提条件

**反直觉结论：** 严格的硬约束不是对自主性的限制，而是赢得自主执行权的敲门砖。

**示例约束体系（SOLUSDT 永续期货实战）：**
- 余额下限：$205（本金 $213，缓冲 $8.10，触底物理中止）
- 单格最大亏损：$22（双重服务端止损，ATR 1.5 倍）
- 杠杆上限：2–3x（脚本验证实际杠杆，不符则中止）
- 部署门槛：8 条件全满足方可执行（RSI、价格位置、趋势、波动率等）

**工程实现要求：** 约束必须在代码层强制执行，而非依赖 Agent 自我判断。

---

## 五、Prop Firm 挑战：验证实盘能力的外部标准

**案例数据（QT Power Prop Firm Challenge）：**
- 周期：约 2–3 周
- 收益：**+7.08%**
- 最大回撤：**< 1%**（远低于 5% 限制）

Prop Firm 规则强制 Agent 在盈利目标与回撤限制之间取得真实平衡，是验证策略能否适应规则约束的低成本测试环境。

## 行动检查清单

- [ ] 新策略强制 30 天纸面交易，记录滑点与延迟数据
- [ ] 所有技术指标改为事件触发（穿越），而非状态检测
- [ ] 部署拒绝日志系统，追踪 `outcome_if_taken` 反事实结果
- [ ] 在代码层（而非 Agent 逻辑层）硬编码关键约束
- [ ] 每月审查拒绝日志：是否有连续 3 次同原因拒绝？
- [ ] 考虑通过 Prop Firm 挑战验证策略实盘表现
