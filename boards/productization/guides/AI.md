# 垂直 AI 产品化：反馈闭环、专家共创与轻量上线

这份 guide 讨论的不是“怎么把 AI 接进产品”，而是怎么把一个具体业务流程尽快做成可上线、可迭代、可被业务 owner 驱动纠偏的垂直系统。

## 1. 先收敛场景，再追求完整

垂直产品化的高胜率起点不是平台化设计，而是围绕一个高频、强痛点、能立刻验证价值的流程收敛。

默认做法：
- 先只打通一条主路径；
- 用最轻的可靠技术栈上线；
- 把“是否被真实使用”放在“是否功能齐全”之前。

## 2. 让领域专家通过真实使用纠偏，而不是靠规格替你想需求

业务 owner 不需要会写代码，也完全可以成为产品设计的核心角色。

高效做法是：
- 快速交出第一版可操作系统；
- 让最懂业务的人亲自点、亲自卡、亲自抱怨；
- 把真实使用中出现的问题当作下一轮产品方向，而不是把长文档当成真相源。

## 3. 垂直产品成败常常输在集成细节，而不是主功能

很多项目并不是功能不会做，而是输在环境假设：
- 时区转换；
- 第三方平台模式切换；
- ID / key 输错；
- 本地化语言和渠道选择错误。

因此上线前必须有一套固定 preflight，而不是临场排查。

## 4. 快迭代必须绑定回归纪律

“当天收到反馈、当天修完上线”很有效，但如果没有最小回归测试，速度很容易变成新 bug 的来源。

推荐默认动作：
- 把反馈拆成功能缺陷 / 体验优化；
- 每轮修复后重走主路径；
- 把踩过的坑写进长期 checklist；
- 把业务 owner 的验收当作产品环节，而不是售后环节。

## 默认执行清单

- 选一个窄流程，先上线再扩边界。
- 第一版必须让业务 owner 能真实试用。
- 上线前固定跑环境 / 集成 preflight。
- 每轮反馈后保留最小回归验证。
- 把踩坑固化成规则库，供下一轮产品直接复用。
