# 内容交付自动化：文档拆解、受众适配与多模态增强

这份 guide 关注的是如何把“做一份 PPT”升级成稳定的内容交付流水线：先理解文档，再生成叙事，再做视觉包装，而不是把格式转换误当成全部问题。

## 1. 先拆解文档，再生成幻灯片

可靠的默认顺序是：
- 提取原文；
- 识别标题、列表、段落与章节关系；
- 生成面向展示的叙事结构；
- 最后才进入模板与版式。

把源文档直接塞进模板，通常只能得到“格式化的原文”，得不到“可展示的内容”。

## 2. audience 决定叙事，不只是语气

内容工作流在生成前必须知道：
- 谁来读；
- 他们想解决什么问题；
- 他们要听到什么结论。

同一份材料，给 CEO、给采购、给项目组、给董事会，叙事骨架都应该不同。

## 3. 多模态增强是可选层，不是主链

AI 配图、视觉增强、成本优化都很有价值，但都应该建立在结构和叙事已经稳定的前提上。

默认原则：
- 图像生成可关；
- provider 可替换；
- 失败可 fallback；
- 成本可设上限。

## 4. 自动化交付也需要 QA

最终验收不能只看“像不像 PPT”，而要看：
- 逻辑是否保真；
- 结论是否清楚；
- 叙事是否匹配受众；
- 增强层是否真的在加分。

## 默认执行清单

- 固定“提取 -> 结构 -> 叙事 -> 渲染”四段流水线。
- 在生成前明确 audience 与场景。
- 让图像步骤保持可选与可 fallback。
- 对输出做结构与叙事双重验收。
- 定期对照纯 LLM 直出结果，验证流水线复杂度是否值得。
